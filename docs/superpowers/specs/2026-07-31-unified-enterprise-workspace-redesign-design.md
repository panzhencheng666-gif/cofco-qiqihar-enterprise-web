# 齐齐哈尔粮食商情企业平台统一工作区重构设计

> 日期：2026-07-31
>
> 状态：待用户确认
>
> 范围：企业平台原型的全局框架、一级入口、业务工作区、填报与履责关系、供需与报告衔接、统一视觉体系

## 1. 目标

本次不是为旧页面更换颜色，而是统一整套系统的业务入口、页面结构和操作逻辑，使普通业务人员可以回答四个问题：

1. 我现在处于哪个组织、地区、产品和期间？
2. 我需要完成什么工作？
3. 这项数据应当在哪里填写、由谁审核、是否已经发布？
4. 当前看到的指标来自哪份已审核数据，能否进入供需和报告？

系统必须同时满足：

- 业务完整但不重复；
- 同类业务集中，不拆散到多个应用；
- 一份业务数据只有一个权威填报位置；
- 我的工作、履责监督和报告只引用业务记录，不复制业务记录；
- 样本、区域估计、正式指标和供需结果明确分层；
- 界面使用全中文业务语言，不出现开发状态、接口名称或实现术语；
- 视觉克制、高密度、稳定，适合长期企业运营。

## 2. 总体信息架构

### 2.1 普通业务用户入口

普通业务用户显示六个一级入口：

1. **我的工作**：本人待填、待改、待审、待发布、异常和已办事项。
2. **经营总览**：已授权正式指标、业务风险和任务摘要，只读展示。
3. **产情监测**：农户、家庭农场、合作社、农技站、行政村台账和田间样方的产情业务。
4. **市场监测**：市场主体、设施、价格、交易、质量、库存、加工、销售和物流业务。
5. **供需与态势**：按产品、地区、营销年度读取已发布指标，完成账户计算、区域平衡和态势分析。
6. **报表中心**：业务日报、周报、月报，履责周报、月报，以及报告复核、发布和历史版本。

“我的工作”和“经营总览”是统一门户，不拥有第二套业务事实。真正的领域应用为产情监测、市场监测、供需与态势和报表中心。

### 2.2 授权管理入口

以下入口只向具备相应权限的人员显示，不占用普通业务人员的主要工作区：

- **数据治理**：行政区划、主体、设施、产品、品种、指标、单位、质量规则、来源映射和数据版本。
- **系统管理**：组织、账号、岗位、角色、安全、审计和运行配置。
- **责任管理**：责任岗位、有效任职、责任范围、报送计划、截止规则和正式责任转移。可从系统管理或履责监督进入。

授权管理人员可以配置责任和查看记录，但不能代替责任人填写业务数据。

## 3. 权威业务链路

统一链路为：

```text
责任与报送计划
→ 当期任务
→ 产情或市场业务单据
→ 质量校验
→ 业务审核
→ 事实发布版本
→ 指标发布版本
→ 供需计算与态势
→ 业务报告
```

约束：

- 我的工作只聚合任务，点击后进入产情或市场原始业务单据。
- 报表中心不提供第二套业务填报表单。
- Excel 导入和系统接入与在线填报共用同一单据、责任、校验和审核流程。
- 供需与态势只读取已发布指标，不成为原始数据写入口。
- 日报、周报、月报引用固定数据版本，不重新计算或重新填报来源数字。
- 履责周报和月报读取固定截止快照，补填不能消除原逾期记录。

## 4. 统一业务坐标

所有工作区共享同一个业务上下文坐标：

```text
组织
＋责任空间
＋地区及区划版本
＋业务域与业务事项
＋对象或对象组
＋作物、商品、具体品种与产品形态
＋业务期间
＋数据截止时点
＋数据或发布版本
```

页面不得写死一个与当前数据不一致的地区、品种或期间。

- 地区只显示当前人员有权限访问的范围。
- 市场监测支持齐齐哈尔指定范围、黑河全域、呼伦贝尔指定范围及授权下级地区。
- 行政村数量只采用带统计日期、来源机关和核验状态的 2025—2026 年权威数据；缺少可靠来源时显示“待核定”，不得使用旧数补齐。
- 村级行政汇总只使用行政村，不使用自然村或自然屯。
- 品种保留填报原值，并显示已确认、待映射或已停用品种状态。

## 5. 状态模型

界面不得再使用一个“状态”同时表达全部含义。每份任务和单据分别显示：

1. **履责状态**：未到期、按时提交、截止未提交、逾期补填、免报。
2. **单据状态**：待填写、填写中、已提交、已退回、已通过。
3. **质量状态**：未校验、通过、警告、阻断。
4. **发布状态**：未发布、候选就绪、已发布、已撤回、已被替代。

颜色只表达状态：

- 青绿色：正常、通过、已发布；
- 琥珀色：待处理、警告、待解释；
- 红色：逾期、阻断、冲突；
- 蓝灰色：普通信息和未开始。

## 6. 各工作区页面结构

### 6.1 我的工作

左侧导航：

- 待我处理
- 待我填报
- 待我审核
- 异常与逾期
- 已办跟踪

首页采用任务工作台，不使用通用业务生命周期大卡片：

- 顶部：本人责任、当前期间、最近截止、待办数量；
- 中部：按紧急程度排序的统一任务表；
- 右侧：今日截止、退回整改和逾期提醒；
- 点击任务直接打开产情或市场对应业务单据；
- 已办记录显示业务来源、提交版本、审核结果和后续发布状态。

### 6.2 经营总览

只读展示已授权信息：

- 产情、市场、供需的正式指标摘要；
- 数据覆盖与审核完成情况；
- 重要风险和异常；
- 最新发布版本与报告；
- 可下钻到对应业务工作区。

不得从经营总览手工维护经营数字。

### 6.3 产情监测

一级工作区保持五个清晰入口：

- 产情总览
- 监测对象
- 数据采集
- 审核发布
- 分析与报告

监测对象只建立一份档案，可包含：

- 农户
- 家庭农场
- 合作社
- 农技站
- 行政村台账
- 田间样方或调查地块

对象档案内集中展示，不拆成多套菜单：

- 玉米、大豆、稻谷及具体品种；
- 播种面积、收获面积、灾损面积；
- 苗情、长势、生育期、灾情、病虫害；
- 测产、预计单产、产量和估计依据；
- 农户余粮、销售事件、自用和损耗；
- 当前正式面积与下一年度种植意愿；
- 生产投入、政策支持、保险及必要的成本保障信息；
- 产品、品种、批次或样品对应的质量指标和检验依据。

数据采集支持在线填报、Excel 批量导入和授权系统接入，三种方式进入同一审核链。

区域指标必须显示来源通道、样本范围、响应率、覆盖率、估计方法、权重或质量等级；未形成正式估计时只显示样本结果。

### 6.4 市场监测

保留已经形成的五个入口：

- 市场总览
- 监测对象
- 数据采集
- 审核发布
- 分析与报告

一个主体只建立一份档案，角色可以多选。主体业务集中在同一工作区，覆盖：

- 贸易商；
- 玉米深加工企业；
- 大豆压榨企业、大豆蛋白加工企业；
- 食品和调味品企业；
- 米厂；
- 饲料企业、养殖企业；
- 储备库；
- 批发市场；
- 种子、农药、化肥经销商；
- 铁路站点和公路物流节点。

价格必须绑定品种、质量条件、数量、计量单位、包装和交付条件。报价、实际成交、库存、加工、销售和物流保持不同事实类型，但在同一主体或节点工作区内连续操作。

市场“分析与报告”只生成市场业务报告，不再重复放置履责周报和履责月报；履责报告统一进入报表中心。

### 6.5 供需与态势

左侧导航：

- 供需总览
- 产品账户
- 区域平衡
- 指标与来源
- 态势分析

每个页面必须首先明确：

- 当前产品账户；
- 市级全域或具体县区；
- 营销年度和截止时点；
- 采用的指标发布版本；
- 当前结果是草案、暂估还是正式发布。

产品账户分别管理玉米、大豆、稻谷和大米，不直接混加不同产品形态。

页面用可读公式展示：

```text
总供给 = 期初库存 + 本期生产 + 区域外流入 + 其他供给
总使用 = 食用 + 饲用 + 种用 + 加工使用 + 损耗 + 区域外流出 + 其他使用
调整前账面期末 = 总供给 - 总使用
采用后账面期末 = 调整前账面期末 + 已批准库存调整
库存平衡差额 = 调查汇总期末 - 调整前账面期末
```

“平衡差额”不得与“期末库存”混为同一概念。任一数值可以下钻查看来源、质量、审核和版本。

市级账户支持全部授权县区下钻；未核定县区明确显示缺失项，不能以零补齐。

### 6.6 报表中心

左侧导航：

- 业务报告
- 履责报告
- 报告复核
- 发布与分发
- 历史版本

业务报告按业务、地区、产品、期间和正式版本生成。可用日报、周报或月报由报告计划决定，不向没有数据基础的业务机械展示全部频率。

履责报告包含：

- 应报、按时、逾期补填、仍未填和免报；
- 按责任人、区域、事项和期间统计；
- 责任周报与责任月报；
- 导出 Word、Excel 和 PDF；
- 固定截止快照和历史版本。

报告生成只能在固定事实范围内组织自然中文，不允许重新计算数字或编造原因。报告必须显示数据截止时间、采用版本、覆盖范围、复核人和修订关系。

## 7. 统一视觉框架

### 7.1 框架尺寸

- 桌面顶部导航高度：64 像素；
- 1440 像素以上左侧导航宽度：176 像素；
- 较窄桌面可折叠为 60—64 像素图标导航；
- 主内容区最大化使用横向空间，不设置装饰性超宽留白；
- 页面内容使用 8 像素基础间距体系。

### 7.2 字体和密度

- 页面标题：24—26 像素；
- 模块标题：15—17 像素；
- 正文与表格：12—13 像素；
- 辅助说明：11—12 像素；
- 表格普通行高：36—40 像素；
- 重要数字根据场景使用 24—32 像素，不再普遍使用巨大指标卡。

### 7.3 页面顺序

业务页面保持稳定阅读顺序：

```text
页面标题与关键操作
→ 当前业务上下文
→ 当前业务范围或对象
→ 核心业务工作区
→ 异常和质量问题
→ 记录、来源与历史版本
```

不再强制每个业务都使用“指标卡＋生命周期＋风险＋通用表格”。

### 7.4 视觉约束

- 深蓝只用于全局导航和重要定位；
- 青绿色用于主要操作和正常状态；
- 红色和琥珀色只用于风险；
- 卡片以边框、分区和对齐建立层级，减少阴影、渐变和装饰；
- 同一系统只使用一套设计变量、按钮、表格、状态和上下文组件；
- 演示数据必须显示“演示环境·非生产数据”，正式环境不显示演示标识；
- 普通页面不得显示代码版本、接口、数据库、内部英文状态码或开发占位语言。

## 8. 异常、空状态与权限反馈

- 无权限：说明当前角色没有访问权限，并提供申请或联系入口。
- 无任务：说明当前期间没有生成任务，而不是展示空白大卡片。
- 数据待核定：显示缺失项、责任单位和核验状态。
- Excel 导入失败：提供行级错误、字段说明和重新导入入口，不产生正式业务记录。
- 系统接入异常：保留最后成功同步时间，异常数据不自动进入审核通过状态。
- 供需输入缺失：阻断正式发布，明确缺失输入，不自动补零。
- 责任冲突：阻断计划生效，不允许产生两个可写负责人。

## 9. 验收标准

1. 全部可见菜单均可进入对应页面，不存在装饰性死菜单。
2. 我的工作、产情、市场、供需和报表中心使用同一套全局框架与视觉变量。
3. 产情和市场拥有各自完整的对象、采集、审核、发布和分析工作区。
4. 从我的工作或履责监督进入填报时，打开的是业务域内同一份单据。
5. 报表中心和市场页面不重复生成履责报告。
6. 地区、产品、期间和版本切换会同步更新页面标题、指标、表格和报告上下文。
7. 产情区域结果明确区分样本结果和正式区域估计。
8. 供需页面完整展示账户公式，期末库存与库存平衡差额含义清楚。
9. 行政区划数据展示统计时点、来源和核验状态，只统计行政村。
10. 业务报告只采用已审核或已发布数据，频率由业务报告计划控制。
11. 1440×900 和 1920×1080 下页面框架无整体横向溢出；复杂表格仅允许表格内部滚动。
12. 页面无技术实现语言、开发占位、伪造官方数值和无业务意义的大模块。
13. 对我的工作、经营总览、产情监测、市场监测、供需与态势、报表中心分别生成验收截图。

## 10. 本轮原型边界

本轮交付重点是统一业务信息架构、关键交互与视觉演示。原型中的业务数值除已注明权威来源的行政区划数据外，均视为演示数据，不代表正式生产统计结果。

涉及服务端唯一责任、不可代填、审计、发布不可覆盖、供需可重现计算和正式文件生成的能力，在正式开发中必须由后端和数据库约束实现，不能仅依赖前端按钮状态。
