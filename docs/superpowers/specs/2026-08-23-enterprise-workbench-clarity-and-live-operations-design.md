# 企业业务工作台清晰化与真实联动设计

日期：2026-08-23

状态：用户已确认按成熟、克制、非卡片化的企业系统方向实施

适用范围：待我处理、已办事项、导入任务、样本点管理、账号与权限，以及产情监测和市场监测的定向可用性优化。

## 1. 目标

系统采用紧凑、方正、表格主导的企业工作台。每个页面只回答一个业务问题：当前要处理什么、已经处理了什么、哪一批导入需要修正、样本网络处于什么状态、账号拥有什么职责。页面不得把开发过程、接口结构或内部实现暴露给业务人员。

## 2. 通用页面骨架

所有普通业务工作台固定使用：

```text
面包屑与页面标题
一句业务说明
紧凑筛选/工具栏
一张核心台账
分页
按需展开的行内详情或右侧处理区
```

- 不使用卡片网格、卡片套卡片、大圆角和阴影。
- 不额外建立没有真实操作的概览块。
- 状态只使用表格列、窄标签和连续摘要。
- 一页最多一个蓝色主要操作，其他操作使用次级或文字按钮。
- 技术状态码、内部ID、接口名、数据库字段名、fixture、mock、调试信息不得出现在业务界面。

## 3. 我的工作

### 待我处理

以本人真实待办为唯一事实来源，按退回/阻断、临近截止、普通待办排序。表格保留：事项、业务范围、期间与截止、责任人、当前状态、处理。点击处理必须打开原业务单据并在成功操作后重新查询。

### 已办事项

沿用同一台账结构，但业务说明和字段语义改为“本人已经处理的事项”。不得复用待办页面的处理提示。结果为零时明确说明当前筛选范围没有已办记录。

### 导入任务

页面采用“业务类型切换 + 批次台账 + 当前行展开详情”。真实能力保持不变：刷新、错误清单下载、仅重试失败行、照片补传和状态重查。不得在首页展示内部批次ID；查看详情时也只展示业务范围和处理结果。

## 4. 样本点管理

页面固定为四个业务模块：

1. 样本点名册：现实调查对象及稳定身份；
2. 设计参考点：2,332 个不分年份的行政村参照；
3. 年度现有样本：2026年起每年度的正式样本网络；
4. 待办审核：坐标修正、身份归并和年度网络审核。

首页不向普通业务人员解释“主数据模型”“稳定身份治理”等开发或架构术语。每个模块只显示一张主表和当前模块可执行操作。历史任务和批量文件操作放在对应模块的次级区域，不堆叠在首页。

## 5. 账号与权限

继续使用真实身份、员工、单位、授权、复核和审计接口。弹窗改为方正的管理工作区：左侧模块导航，右侧单一内容区。

- 我的账号：以定义列表显示本人姓名、单位、岗位、角色、账号状态和责任地区摘要；
- 当前单位：显示单位职责与当前账号在该单位的身份；
- 员工与授权：员工台账和授权编辑；
- 权限复核：复核任务表和按需展开的处理明细；
- 审计追溯：筛选栏和操作记录表。

责任地区不得铺满行政区代码；默认显示业务名称摘要，可搜索或按树形范围查看。只有审计确有必要时才显示业务编号，并使用业务名称解释其含义。

## 6. 产情监测与市场监测

核心采集表和真实业务链路已经成立，不重做领域架构，只进行以下定向优化：

- 筛选条件按年份、月份、地区、样本类型、状态的业务顺序排列；
- 高频操作置于表格工具栏，低频批量操作归入“更多操作”；
- 冻结序号、数据时间、样本点名称和最右操作列；
- 表头分组保持业务口径，横向滚动不能丢失当前对象；
- 2025年及以前的数据明确标注为历史业务记录，不称为年度现有样本；
- 2026年起的现有样本资格从年度网络读取，不能由历史填报记录推断；
- 无记录时说明当前年份、产品、地区和状态范围，并保留新建与导入入口；
- 填报、编辑、提交、审核、退回、模板下载、批量导入、修正和重试继续使用8090权威服务。

## 7. 实时联动和完整功能

- 所有查询、写入、下载和审核均使用8090权威接口；
- 写操作成功后立即重新查询当前业务对象；
- `/api/v1/business-events/stream` 到达后刷新受影响的待办、业务台账、样本网络、地图和分析页面；
- 自动刷新保留当前筛选、页码、模块和选择对象；
- 刷新失败时明确显示可恢复状态，不用旧数据冒充最新结果；
- 测试夹具只允许出现在测试或明确的非实时开发模式，不得进入63182实时模式。

## 8. 验收标准

- 五个工作与权限页面不再依赖卡片堆叠表达业务层级；
- 普通业务人员从标题、工具栏、表头和主要按钮即可判断本页用途与下一步；
- 产情和市场核心业务表格保持可用并完成定向优化；
- 真实接口、权限、审计、下载、重试、提交和实时事件链路均保留；
- 页面不出现开发术语、内部状态码、无业务解释的ID或静态假数据；
- Node 24 定向测试、构建、受管63182同步、哈希和浏览器业务验收通过后才报告完成。
