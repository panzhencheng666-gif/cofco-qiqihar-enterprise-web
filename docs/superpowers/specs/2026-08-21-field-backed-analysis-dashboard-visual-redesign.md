# 产情、市场与供需经营看板视觉重构设计

## 文档状态

本文是 2026-08-21 分析三页视觉呈现的最终权威规格，并仅替代《业务分析报告与导入台账统一设计》中“连续表格式指标带、不使用独立指标卡”的视觉段落。报告生成、核定数据语义、缺失不补零和导入任务台账仍由前述设计约束。

## 目标

将产情分析、市场分析和供需平衡从纵向数据报表重构为紧凑、图表优先、层级清晰的经营看板。版式参考用户提供的经营总览图片，但所有指标、图形和明细仍只来自现有核定填报字段与服务端权威计算。

## 业务边界

- 唯一数值来源为现有 `ObservableAnalysisSnapshot`、年度快照序列及供需计算结果。
- 前端不得补造目标值、达成率、风险排名、健康度、经营诊断或静态演示数据。
- 指标值为空、缺少核定样本或服务端不能计算时，不绘制对应图形，也不补零。
- 同一个比例轴只比较同单位指标；不同单位必须拆成独立图组。
- 只有两个及以上真实有效月份才绘制趋势；单期只展示本期结构。
- 数据刷新继续沿用现有查询和实时刷新机制，视觉层不得缓存独立业务值。

## 信息架构

页面从上到下固定为五层：

1. 紧凑工具栏：标题、简短业务副标题、刷新、产品、年份、月份与地区范围。
2. 核心指标带：最多六张真实指标卡，显示服务端数值、单位和核定来源数。
3. 主图表区：7:5 双列，左侧呈现页面主业务关系，右侧呈现结构或构成。
4. 辅助图表区：最多三列，只渲染具有有效业务字段的结构、质量、覆盖或趋势图。
5. 核定来源区：页面底部限高滚动，保留追溯能力但不占据首屏主视觉。

主视觉在普通桌面首屏内必须出现核心指标带和至少一组完整业务图表。筛选区不得再占据大面积空白。

## 页面映射

### 市场分析

- 指标带：核定收购价格、核定销售价格、购销价差、采购量、销售量、当前企业库存。
- 主图左：价格组和购销数量组分区呈现，分别使用独立比例轴。
- 主图右：库存及车板、包装、运费等实际存在的流通字段；不同单位拆分为小图组。
- 辅助区：包装结构、质量区间和数据覆盖，仅在对应指标存在时显示。

### 产情分析

- 指标带：播种面积、亩均产量、总产量及现有成本、灾损、库存类核心字段。
- 主图左：生产规模与产出，面积、单产、总产量按单位分组展示。
- 主图右：亩均成本构成，只汇总服务端已返回的同单位成本项。
- 辅助区：灾损与种植意向、质量区间、库存与去向，仅按实际字段渲染。

### 供需平衡

- 指标带：服务端供需计算已返回的生产、供给、需求和库存结果。
- 主图左：供需流向桥。缺失环节显示缺口，不将其作为零参与绘制。
- 主图右：采用日期明确的库存分解与对比。
- 辅助区：真实月份趋势、生产主体勾稽、覆盖范围与记录数。

## 图表与视觉规范

- 画布采用与现有蓝色平台壳体协调的浅灰白底；经营卡片使用白色、细边框和低对比阴影。
- 酒红色仅用于页面重点和状态提示；数据图形使用青绿与蓝色，不使用装饰性渐变堆叠。
- 数值字体采用系统中文无衬线与等宽数字特性，单位紧邻数值，不牺牲精度。
- 条形图必须在图形末端直接显示数值；占比图必须同时显示名称、比例和样本数。
- 不增加图表依赖，使用现有 React、CSS 和 SVG 组件完成。
- 响应式布局按可用内容宽度调整为六列、三列或两列，不造成页面横向滚动。

## 控件与明细

- 筛选器压缩为紧凑两行；地区级联仍保留全部业务选择能力。
- 长选项继续使用带箭头的原生下拉控件，系统菜单提供滚动；不得无限延长页面。
- 核定来源使用限高滚动容器，表头保持可辨识；不得删除真实来源和核定时间。
- 界面不出现版本号、接口名称、开发说明、英文状态或实现术语。

## 验收标准

- 三页首屏均出现紧凑筛选、真实指标卡和主图表。
- 页面不存在无字段支持的静态指标或图形。
- 单期页面不存在伪趋势，缺失值不存在补零。
- 市场不同单位不共用比例轴；产情成本项只比较同单位字段；供需缺口不参与数值绘制。
- 来源明细不会把页面撑成超长报表。
- Node 24 定向测试和构建通过，63182 页面与 8090 权威接口数值一致，浏览器无相关控制台错误。

## 自检

- 无占位内容、待定字段或示例数值。
- 所有视觉槽位均有现有快照字段映射，布局组件本身不能创建业务值。
- 范围仅包含三张分析页面，不进入导入台账、照片、坐标、身份或其他相邻模块。
