# 齐齐哈尔粮情企业平台视觉融合增补设计

> 日期：2026-07-31
>
> 状态：待用户书面复核
>
> 适用范围：独立界面样板 A 方案
>
> 目标：以参考图的企业级完成度承载已经确认的业务架构，不恢复旧版的业务混排

## 一、已选择的方向

本轮比较过三种处理方式：

1. 保留现有 A 方案，只提高字号、阴影和间距；
2. 按参考图逐项复制导航、卡片和工具栏；
3. 保留当前业务边界与责任版本链，吸收参考图的企业壳层、操作台层次和组件精度。

选择第三种。

第一种无法解决“像设计稿、不像成熟生产系统”的问题；第二种会把参考图中尚未验证的菜单组织、动作和对象关系一并复制。第三种可以同时获得视觉完成度、连续操作感和可审计的业务逻辑。

## 二、不变的业务架构

视觉升级不得改变以下边界：

- 一级工作空间仍为“我的工作、产情监测、市场监测、供需平衡”；
- 产情监测保持行政村台账、农技站观测和农户抽样三类来源独立治理；
- 市场监测保持报价、交易、库存、加工和物流事实独立；
- 供需平衡只采用已经发布的规范事实和指标；
- “责任组织、当前岗位、业务期间、数据截止、质量资格、审核状态、发布版本”保持连续可见；
- 普通业务界面不显示开发语言、框架术语、英文技术标识或内部异常堆栈；
- 样板继续标注“界面样板｜非正式数据”，不连接数据库或正式服务。

## 三、正式融合型页面结构

推荐 A 方案由“责任轨道型”升级为“正式融合型”，B 和 C 继续保留用于对照。

```text
┌──────────────────────────全局企业顶栏──────────────────────────┐
│ 应用入口 │ 品牌 │ 组织 │ 当前应用 │ 全局搜索 │ 环境/通知/帮助 │ 用户 │
├──────────────┬──────────────────────────────────────────────┤
│ 当前业务应用   │ 面包屑                         页级业务动作      │
│ 应用名称与说明 │ 页面标题与任务说明                              │
│              ├────────────────业务上下文带────────────────────┤
│ 分层业务导航   │ 组织 │ 区域 │ 年度 │ 品种/对象 │ 数据范围 │ 版本状态 │
│              ├────────────────页面内导航──────────────────────┤
│              │ 运营总览 │ 对象/账户 │ 任务 │ 审核发布 │ 质量 │ 来源版本 │
│              ├──────────────────────────────────────────────┤
│              │ 经营指标区                                    │
│              ├───────────────────────┬──────────────────────┤
│              │ 本期生命周期与主作业区  │ 需要立即处理            │
│              ├───────────────────────┴──────────────────────┤
│              │ 对象、任务或账户明细表 + 筛选与列设置             │
└──────────────┴──────────────────────────────────────────────┘
```

### 3.1 全局企业顶栏

顶栏恢复完整的企业平台语义：

- 九宫格应用入口；
- 平台标识和“经营监测与区域研判”副标题；
- 当前组织选择；
- 当前业务应用选择；
- 全局搜索；
- “样板环境”标识；
- 任务、通知和帮助入口；
- 当前用户、岗位和账号入口。

顶栏只表达跨应用能力，不放产情或市场的页内动作。

### 3.2 分层业务侧栏

侧栏不再只有四个大入口，而是分为两层：

- 顶部显示当前业务应用及其业务用途；
- 主导航显示当前应用的正式工作区；
- 底部显示数据服务、同步时点和会话状态。

不同一级工作空间使用不同导航：

- 我的工作：待我处理、待我审核、异常与逾期、待发布、已办跟踪；
- 产情监测：产情总览、种植生产、农户库存与销售、种植意愿、质量与发布；
- 市场监测：市场总览、主体与设施、行情与交易、库存与仓储、加工与消费、物流与流向；
- 供需平衡：供需总览、产品账户、账户勾稽、版本与血缘。

全局四个入口放入顶栏的当前应用选择器，不与侧栏工作区重复。

### 3.3 页面标题与动作

标题区包含：

- 面包屑；
- 页面正式名称；
- 一句任务说明；
- 与当前页面直接相关的页级动作。

动作按页面区分，不统一堆放：

- 我的工作：批量领取、转交规则；
- 产情监测：导入调查结果、导出当前视图、新建调查任务；
- 市场监测：导入报送、导出当前视图、新建采集任务；
- 供需平衡：比较版本、查看口径、新建测算草案。

所有动作在样板中仅展示交互位置，不模拟正式提交。

### 3.4 业务上下文与责任版本

原来的大型七段轨道压缩为 64–72 像素的业务上下文带，合并相邻信息但不丢失状态：

- 当前责任上下文；
- 组织；
- 区域；
- 业务年度或期间；
- 品种或业务对象；
- 数据范围与截止时点；
- 质量、审核和发布版本。

质量、审核和发布使用文字加状态色，不只依赖颜色。

### 3.5 主工作区

首屏按“判断—处置—明细”组织：

1. 指标区说明本期规模、进度、资格和异常；
2. 生命周期说明当前业务处于哪一步、下一责任人是谁；
3. 右侧异常区只显示影响质量资格或发布的事项；
4. 明细表承担持续工作，不以卡片代替任务、对象或账户；
5. 来源与版本作为表格页签或底部资格区出现，不占据首屏主视觉。

## 四、四个页面的首屏差异

### 4.1 我的工作

- 指标：待处理、待审核、质量阻断、本周按期率；
- 生命周期：任务受理、处理、复核、审核、发布；
- 主表：事项、业务域、当前状态、责任岗位、完成时限；
- 右侧：影响今日发布和已经逾期的事项。

### 4.2 产情监测

- 页面名称：“种植生产运营工作区”；
- 指标：有效监测对象、采集完成率、待审核退回、阻断性质量异常；
- 生命周期：任务下达、调查采集、规则校验、分级审核、正式发布；
- 主表：样本对象、来源类型、行政区划、本期任务、业务状态、质量状态、当前责任人、时限；
- 三类来源在来源与版本页签中分别显示资格，不合并成一个调查来源。

### 4.3 市场监测

- 页面名称：“市场运行监测工作区”；
- 指标：有效主体、采集完成率、库存异常、价格与流向预警；
- 生命周期：任务下达、主体报送、事实匹配、业务审核、指标发布；
- 主表：市场主体、事实类型、区域、采集任务、业务状态、质量状态、责任人、时点；
- 报价、交易、库存、加工和物流保持独立事实类型。

### 4.4 供需平衡

- 页面名称：“玉米供需账户工作区”；
- 指标：总供给、总使用、期末库存、勾稽差额；
- 生命周期：版本创建、指标采用、账户计算、差额解释、审核发布；
- 主表：账户项、事实或指标来源、采用版本、数量、资格、责任人；
- 账户等式放在主工作区，不使用产情或市场的调查任务布局。

## 五、视觉系统增补

### 5.1 色彩

继续使用已经确认的六色体系：

- 全局深蓝 `#0B2A3B`；
- 治理青绿 `#167C74`；
- 业务画布 `#F3F6F8`；
- 数据纸白 `#FFFFFF`；
- 结构分隔 `#D6E0E6`；
- 风险琥珀 `#B88318`。

参考图的成熟感通过层级、间距、控件和排版实现，不复制其颜色值。红色仅用于阻断。

### 5.2 字体与密度

- 页面标题使用本地中文黑体或宋体中的稳定字重，不再过度追求设计感；
- 正文与表格最低可读字号提高，不以缩小文字换取密度；
- 数字使用等宽数字；
- 1440×900 首屏必须看到标题、上下文、主要指标、生命周期、异常和主表表头；
- 主表正文允许首屏显示 3–5 行，其余滚动。

### 5.3 控件完成度

统一完善以下状态：

- 默认、悬停、聚焦、当前、禁用；
- 正常、提醒、警告、阻断；
- 加载、空状态和无权限状态只在正式实现阶段补充，样板不伪造；
- 图标用于识别应用、动作和状态，不作为装饰；
- 阴影只用于顶栏、浮层和明确悬浮关系。

### 5.4 识别性元素

平台的独有元素仍是“责任与版本轨道”，但它从大型流程条变为嵌入业务上下文的连续状态带。

本期业务生命周期另行表达操作进度，两者不得混为一条：

- 责任与版本轨道回答“谁负责、用什么期间和版本、是否可发布”；
- 生命周期回答“业务已经执行到哪一步、下一步做什么”。

## 六、明确删除

升级 A 方案时删除：

- 侧栏与页签中重复出现的同名入口；
- 过大的责任轨道；
- 仅为填满页面存在的来源卡片；
- 英文导航缩写和开发式版本编号；
- 所有页面完全相同的动作按钮；
- 装饰性序号、渐变和无状态含义的彩色圆点。

## 七、验收标准

升级后的样板必须满足：

1. 第一眼达到参考图相同级别的企业平台完整度；
2. 无遮罩时在 1440×900 下清晰可读；
3. 四个页面具有同一壳层但不同业务主体；
4. 顶栏、侧栏、上下文、页签、指标、生命周期、异常和明细表层级清楚；
5. 责任版本链和业务生命周期没有混为一谈；
6. 产情、市场、供需业务边界未因视觉融合而改变；
7. 普通界面不出现技术语言或内部英文编码；
8. 页面、方案和键盘切换可用；
9. TypeScript、代码检查、独立构建和既有自动测试通过；
10. 输出“我的工作、产情监测、市场监测、供需平衡”四张 1440×900 展示图供用户最终确认。
