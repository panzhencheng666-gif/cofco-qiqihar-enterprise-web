# 齐齐哈尔粮食商情企业平台正式生产系统设计

日期：2026-08-08  
状态：待用户书面复核  
适用范围：`cofco-qiqihar-enterprise-web`、`cofco-qiqihar-enterprise-frontend`、`cofco-qiqihar-enterprise-backend`、`cofco-qiqihar-enterprise-infrastructure`

## 1. 目标与原则

本设计将现有 enterprise 项目建设为一个可正式上云的大企业级粮食商情业务系统。系统在业务和用户认知上保持唯一，不创建第二套平台，不恢复旧 dashboard。

设计原则：

1. 保留现有顶部导航、左侧业务目录、蓝色视觉体系、品牌和总揽地图风格。
2. 企业化改造集中在领域边界、数据契约、权限、审计、可靠性和运维体系，不以视觉重做替代业务建设。
3. 任何可见按钮都必须连接真实页面、权限、API 和持久化能力；尚未完成的功能默认隐藏，不允许空弹窗或装饰入口上线。
4. 生产环境禁止使用演示数据、前端固定业务数据或失败后回退到模拟数据。
5. 总揽监测只展示由业务平台填报、审核并存入后端数据库的正式数据。
6. 业务界面只出现业务语言。端口、API、数据库版本、环境名、内部异常栈等技术信息仅进入受控日志和运维平台。

## 2. 架构选择

采用“模块化单体 + 企业基础设施”的架构，不在当前阶段强制拆分微服务。

### 2.1 单一系统与运行组件

系统对外使用统一域名、统一网关、统一身份和统一权限。内部包含：

- 业务平台：产情、市场、物流、供需、报表和我的工作。
- 总揽监测：地图、指标、趋势和区域钻取。
- 业务 API：承载领域规则、流程、权限和聚合查询。
- PostgreSQL/PostGIS：承载业务数据、审计数据和空间数据。
- 对象存储：承载现场水印照片及报告文件。
- 统一认证服务：承载登录、退出、账号安全和登录设备。
- 可观测性设施：日志、指标、链路、告警和审计检索。

业务平台和总揽监测是同一系统的两个视图，不是两个独立系统。两个前端通过同一网关访问版本化 API，不相互读取页面状态。

### 2.2 后端领域模块

后端保持模块化单体，并按以下领域建立清晰边界：

- 身份、组织与权限
- 主数据
- 产情监测
- 市场监测
- 物流监测
- 供需平衡
- 报告中心
- 工作流与待办
- 通知
- 文件与现场凭证
- 总揽聚合
- 审计与合规

领域模块只能通过应用服务、明确接口或领域事件协作，禁止跨模块直接修改对方表。未来确需服务化时，按这些边界拆分，不推翻领域模型。

### 2.3 数据同步

正式数据链路为：

`业务填报 → 领域校验 → 草稿保存 → 提交/审核 → 正式数据版本 → 聚合计算 → 总揽监测`

审核完成、退回、修订和发布产生不可丢失的业务事件。数据库事务同时写入业务数据和 outbox 事件；后台投递器异步刷新总揽聚合和通知。总揽接口返回数据版本、业务期间和更新时间，但普通界面不展示内部基础设施信息。

## 3. 界面与交互

### 3.1 保持不变

- 顶部主导航与左侧业务目录
- 当前品牌名称、Logo 和蓝色视觉风格
- 总揽监测地图和大屏视觉语言
- 产情、市场、物流、供需、报表和我的工作入口

### 3.2 填报工作台

所有产情、市场和物流填报页面采用同一交互模式：

1. 默认进入记录列表，不显示完整填报表单。
2. 列表提供真实查询、分页、查看、编辑、提交、审核和退回动作。
3. 点击“新建填报”后进入独立表单状态。
4. 点击记录进入只读详情；有权限且状态允许时可切换编辑。
5. 保存或取消后返回原列表页，并保留合法查询条件和分页位置。
6. 浏览器刷新、前进和后退必须保持确定的路由状态。
7. 禁止在同一页面同时渲染真实数据库工作台和旧原型工作台。

### 3.3 查询条件

常用筛选区保留：

- 地区
- 调查批次/业务期间
- 对象类型
- 具体品种
- 填报状态

单日“调查日期”从常用区删除。如确有需要，在“更多筛选”中提供日期范围。保留查询和重置。只有完成用户级持久化契约后才显示“保存常用条件”。

### 3.4 通用填报增量字段

在每种业务原有字段基础上增加，而不是替换原业务字段：

- 填报人：必填，由当前认证身份带出并持久化主体标识和显示快照。
- 客户联系方式：必填，按权限脱敏展示。
- 经度：必填，范围 `[-180, 180]`。
- 纬度：必填，范围 `[-90, 90]`。
- 现场水印照片：必传，至少一张。

照片保存原文件、内容摘要、拍摄时间、照片定位、上传时间、上传主体和关联业务记录。服务端校验文件类型、大小、数量和摘要；照片权限继承业务记录地区权限。

### 3.5 产情字段调整

保留现有面积、长势、生育阶段、质量、成本、保险、补贴、预计单产和预计总产等业务字段。

删除：

- 现场依据
- 病虫害与灾情
- 样本平均单产
- 区域加权单产
- 测产轮次

“数据来源”改为现场水印照片。供需平衡的本地生产继续采用审核后的预计总产，不依赖被删除的三个测产辅助字段。

### 3.6 市场字段调整

删除市场填报中的：

- 入库数量
- 损耗数量

“损耗”作为供需平衡计算项继续保留，但必须来自供需模块的独立来源或人工核定，不再从市场填报字段读取。删除字段不得破坏历史记录读取；旧数据保持只读兼容，新版本停止采集。

### 3.7 物流监测

物流监测使用与产情、市场一致的列表、详情、新建、编辑和审核模板，并按玉米、大豆、稻谷分品种。物流字段由后端定义和适用性契约决定，前端不得硬编码一套跨品种表单。

### 3.8 分析页面

产情分析和市场分析是独立只读分析工作区，不复用填报表单。

产情分析展示当期与前三年同地区、同品种、同期间口径下的：

- 播种面积、预计收获面积、预计单产和预计总产
- 长势与生育阶段分布
- 质量和成本指标
- 同比变化、趋势和数据覆盖率

市场分析展示当期与前三年同口径下的：

- 采购基础价、销售基础价、实际成交价
- 购销数量、库存和价差
- 同比变化、趋势和数据覆盖率

不足三年时明确展示缺少年份和覆盖率，禁止用模拟值补齐。

### 3.9 供需平衡

供需平衡主页面用于展示：

- 输入来源及其审核版本
- 供给项和使用项
- 公式、计算步骤和中间结果
- 校验结果、平衡差额和最终结果
- 计算时间、采用版本和发布状态

配置来源和人工核定属于有权限的业务动作，不作为普通用户打开页面时常驻的大型录入表单。

## 4. 报告中心

删除“综合报告”，保留“业务报告”。

生成报告或一键导出前必须选择：

- 报告类型：产情、市场、物流或供需平衡
- 地区：具体地区或授权范围
- 品种：具体品种或全部品种
- 时间：具体期间或受限时间范围

允许生成较大范围报告，但必须遵守组合限制：

- 地区和品种都为“全部”时，只允许一个业务期间。
- 扩大时间范围时，必须缩小地区或品种范围。
- 生成前展示预计记录数、覆盖地区、品种、期间和缺失数据。
- 超过服务端数据量、文件大小或执行时间上限时阻止生成，并给出业务化缩小范围建议。

报告只使用已审核数据。后端保存报告参数快照、来源记录版本、生成主体、生成时间、文件摘要和审计轨迹。前端不得在浏览器内拼接正式报告数据。

## 5. 顶部工具与账户菜单

删除：

- 个人中心
- 组织、岗位与责任范围
- 代理与工作交接
- 切换账号
- 无行为的工作单位下拉菜单

保留并实现真实能力：

- 待办：后端待办列表、真实数量、状态、权限和业务深链接。
- 通知：通知列表、未读数、标记已读、业务深链接和事件来源。
- 帮助：按当前业务页面提供版本化业务说明，不展示开发信息。
- 常用条件与显示偏好：用户级持久化、跨设备读取和恢复默认。
- 账号安全与登录设备：由正式统一认证服务提供。
- 退出登录：撤销会话并返回统一登录入口。

账号安全、登录设备和退出登录在正式认证未接通时不显示。顶部工作单位只读展示；不提供无实际行为的切换选项。

全局搜索必须改为后端授权搜索，只返回当前主体有权查看的页面、记录、任务和报告。完成前不得使用前端固定业务对象或报告数据。

## 6. 契约与数据治理

### 6.1 契约

- 版本化 REST API 和统一错误模型。
- OpenAPI 或等价机器可读契约作为前后端唯一 DTO 来源。
- 前端对关键响应执行运行时结构校验，不仅依赖 TypeScript 类型断言。
- 数据库字段、Java DTO、领域值对象、API 契约和 TypeScript 模型建立自动一致性测试。
- 删除字段采用兼容迁移：先停止写入、保持历史读取，再完成归档或物理删除。

### 6.2 主数据

地区、品种、对象类型、业务期间、字段定义、单位和适用性由后端主数据管理。前端不维护生产用副本。

### 6.3 状态机

业务记录使用明确状态：草稿、待审核、已退回、已批准，以及必要的已撤回或已作废。服务端决定允许动作；前端仅展示服务端返回的动作集合。

所有写操作使用乐观锁。导入、报告生成和可重试命令使用幂等键和数据库唯一约束。

## 7. 安全与合规

正式上线前必须完成：

- 接入正式 SSO/OIDC 或等价企业认证，禁止以客户端可控请求头直接建立身份。
- 所有列表、详情、分析、报告、工作流和总揽接口执行地区级对象授权。
- 客户联系方式按角色脱敏，并记录访问审计。
- 照片和报告使用私有对象存储、短时授权下载和恶意文件检测。
- 修复并发导入幂等竞争。
- 对 CSV 行数、JSON 字节数、集合基数、文本长度和十进制语法设置硬限制。
- 密钥通过云密钥管理注入，禁止写入代码、镜像或仓库。
- 生产环境禁止启用 local profile、演示模式或开发身份引导。

## 8. 错误处理

- 后端不可达、响应契约错误或数据不完整时失败关闭，不回退演示数据。
- 普通用户看到业务化提示、可恢复动作和追踪编号。
- 技术栈、端口、SQL、异常栈和内部版本只进入受控日志。
- 保存失败不清空表单；并发冲突提示刷新或对比，不静默覆盖。
- 照片上传支持明确进度、失败重试和去重。
- 报告生成采用后台任务，支持状态查询、失败原因和受控重试。

## 9. 云端部署

统一网关对外提供 HTTPS，路由业务平台、总揽监测、API 和认证回调。生产部署必须覆盖完整业务平台，不得只部署总揽前端。

环境至少包含开发、测试、预生产和生产。配置和数据严格隔离。数据库迁移在发布前演练，并具备回滚或前向修复策略。

上线能力包括：

- 不可变镜像和制品签名
- 健康检查、就绪检查和优雅停机
- 灰度发布和快速回滚
- 数据库备份、对象存储版本保护和恢复演练
- 指标、日志、链路追踪和告警
- 容量、性能和故障演练

## 10. 测试与上线门禁

### 10.1 自动测试

- 领域单元测试
- 数据库迁移空库重放和升级测试
- API 集成测试
- 前后端契约测试
- 每个可见按钮的浏览器 E2E 测试
- 权限、地区隔离和越权测试
- 照片上传、下载、权限和异常文件测试
- 报告范围、数据量上限和来源版本测试
- 总揽与已审核业务数据一致性测试
- 并发、幂等和乐观锁测试
- 性能、容量和长时间稳定性测试
- 安全扫描和人工验证

### 10.2 按钮验收

建立按钮能力清单。每个入口必须记录：所在页面、用户角色、前置状态、调用 API、数据库影响、成功结果、失败结果和自动化用例。缺少任何一项的入口不得上线显示。

### 10.3 发布阻断条件

出现以下任一情况禁止部署生产：

- 可见空壳按钮或演示数据
- 前后端或数据库契约不一致
- 地区越权或身份伪造风险未关闭
- 业务平台未包含在正式部署拓扑
- 备份恢复未演练
- 关键 E2E、契约、安全或性能门禁失败
- 总揽指标无法追溯到已审核业务记录
- 正式行政边界数据缺少合法来源与使用许可

## 11. Git 与交付方式

按小批量、可审查、可回滚的方式交付：

1. 设计规格
2. 数据库兼容迁移和领域契约
3. 后端 API 与安全闭环
4. 业务平台列表/表单重构
5. 分析、供需和报告
6. 总揽实时联动
7. 顶部工具和统一认证
8. 云端基础设施与可观测性
9. 全量验收与发布演练

每一阶段独立测试、独立提交，不混入无关工作。当前仓库尚未配置 GitHub remote；配置正式远程仓库前，不执行推送或创建 PR。

## 12. 验收结果

完成本设计后，用户看到的仍是现有齐齐哈尔粮食商情企业平台，但所有可见业务能力均由真实后端和数据库支撑；总揽监测与业务填报实时联动；系统具备正式认证、地区权限、审计、可观测性、恢复和发布能力，可以进入生产上线审批。
