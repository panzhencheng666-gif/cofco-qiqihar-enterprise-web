# 样本点独立填报页与 XLSX 原子导入设计

日期：2026-09-02

状态：页面方向与导入事务规则已由用户确认，等待书面规格复核

适用范围：设计样本点、正式样本稳定信息、按对象类型填写或更新期间业务数据，以及这些写操作与台账、总揽、地图、统计和分析页面之间的实时同步。

## 1. 决策摘要

样本点维护不再使用右侧抽屉、小栏、局部详情卡或嵌在台账下方的编辑卡片。系统采用可刷新、可前进后退的独立页面流转：

```text
业务台账 → 样本维护清单 → 新增/编辑样本完整页面
                       └→ 填写/更新最新业务数据完整页面
```

删除不进入填报页，在样本维护清单中显示明确影响说明并二次确认。

设计样本点和正式样本点都提供真实 XLSX 批量导入。所有导入只有一个业务过程：

```text
上传 XLSX → 系统一次自动校验 → 整批直接写入数据库 → 权威重查与实时联动
```

任一数据行不合格时整批不入库，并返回逐行错误明细。系统不设置草稿、提交审核、二次校验、批准、发布或人工复核环节。

## 2. 业务对象边界

### 2.1 设计样本点

设计样本点是不随年份变化的参考点，维护业务类型、产品、对象类型、行政区、名称、地址、坐标及后端字段契约要求的其他稳定信息。不得写入调查年度或期间业务事实。

### 2.2 正式样本稳定信息

正式样本描述长期调查对象的稳定身份，包括名称、行政区、地址、坐标、当前对象类型和维护人。修改稳定信息不覆盖、不复制历史期间记录。

### 2.3 期间业务数据

期间业务数据属于正式样本在指定业务域、产品和观测时间下的事实记录。点击“填写采集数据”或“更新采集数据”时，系统必须以最新正式样本详情中的对象类型为准，从后端读取适用字段定义。

更新页只允许修改当前对象适用的最新业务字段；样本名称、地区、坐标、对象类型和维护人保持锁定。对象类型如需变更，必须先在正式样本稳定信息编辑页完成，之后重新进入业务数据更新页。

## 3. 页面与路由

### 3.1 可恢复路由

现有业务栏目地址继续保留，在其后增加页面层级和当前对象标识。页面层级必须写入地址，而不是仅保存在 React 局部状态中。刷新、浏览器前进和后退后应恢复到同一业务页，并重新读取权威数据。

页面类型至少包括：

- 业务台账；
- 正式样本维护清单；
- 正式样本新增；
- 正式样本稳定信息查看；
- 正式样本稳定信息编辑；
- 正式样本期间业务数据填写或更新；
- 设计样本点清单；
- 设计样本点新增；
- 设计样本点查看；
- 设计样本点编辑。

地址中的技术标识只用于定位对象，不在页面正文、表格列或错误提示中展示内部 ID。

### 3.2 台账页

台账页只承担查询、展示和进入业务操作：

- 保留年度、月份、地区、对象类型、状态和关键词等现有有效筛选；
- 单一台账呈现，不恢复“采集台账、正式样本台账、已有样本数据更新”三类标签；
- 行级操作统一位于表格最右列；
- “样本维护”进入完整维护清单页；
- “填写采集数据”或“更新采集数据”直接进入该样本的完整业务填报页；
- 返回台账时恢复原有筛选、页码和滚动上下文，并执行一次权威重查。

### 3.3 样本维护清单页

正式样本和设计样本各自拥有一个完整维护清单页。页面使用标题栏、筛选工具栏、主表和分页，不使用左右分栏详情卡。

主要操作位于标题栏或表格工具栏：

- 新增样本；
- 下载 XLSX 模板；
- XLSX 批量导入；
- 查询与重置。

行级操作为查看、编辑、删除；正式样本根据权限额外提供指定或改派维护人、填写或更新业务数据。查看和编辑进入完整页面，不在表格旁展开卡片。

### 3.4 新增和稳定信息编辑页

页面从上到下固定为：

```text
面包屑与返回入口
页面标题、对象类型和当前状态
基础身份信息
行政区与地址
坐标信息
业务归属与维护责任
校验或服务端错误
固定操作栏：保存、取消
```

表单使用连续分区、清晰分隔线和桌面双列或三列栅格，不使用一组独立卡片堆叠。窄屏按一个字段一行排列，不产生横向溢出。

新增或修改成功后，前端使用服务端返回标识重新读取详情；只有权威详情读取成功后才显示“保存成功”，随后返回维护清单并重新查询。

### 3.5 期间业务数据填写或更新页

页面顶部显示只读的样本名称、对象类型、业务地区、维护人、产品和实际观测时间。内部编码不对用户展示。

字段区由后端字段定义生成：

1. 读取最新正式样本详情并锁定样本身份；
2. 根据当前业务域、产品和样本对象类型读取字段定义；
3. 只展示该对象类型适用的业务字段，并使用业务中文名称、单位、必填规则、精度和选项；
4. 更新最新数据时预填当前权威最新值，同时显示最近正式入库时间；
5. 历史记录以页面下方的紧凑表格呈现，不使用历史卡片墙；
6. 保存时只提交当前字段定义允许的字段，后端再次按同一权威定义执行写入约束；
7. 成功后重新读取最新数据并返回来源台账，来源台账同步刷新。

维护人、地区和权限不满足时，页面只显示明确业务原因，不渲染可提交的假表单。

## 4. XLSX 批量导入

### 4.1 入口与模板

设计样本点维护页和正式样本维护页分别提供自己的模板和导入入口，不能共用含义模糊的通用文件。

- 模板由后端生成，列名、必填项、枚举值和版本与当前字段契约一致；
- 模板只用于批量新增样本，已有样本的修改使用独立编辑页，避免依赖用户不可见的内部 ID；
- 重复名称、重复坐标或其他业务冲突由权威服务按现有约束拒绝；
- 期间业务数据如提供 XLSX 导入，模板必须绑定业务域、产品和对象类型，且遵循本节同一原子规则。

### 4.2 一次自动校验

用户选择文件并确认导入后，页面只显示“正在校验并导入”。后端在任何写入前一次性完成：

- 文件类型、大小、工作表、表头和单元格安全校验；
- 必填、长度、数值、精度、枚举和字段契约校验；
- 行政区、对象类型、产品、维护人和当前账号权限校验；
- 坐标范围、行政区边界和重复冲突校验；
- 文件内重复行及数据库既有记录冲突校验。

这是一条自动处理链，不产生草稿状态或待审核状态，也不要求用户再点一次“提交”或“确认入库”。

### 4.3 原子入库

- 全部行通过：同一事务写入全部记录、审计信息和业务事件；
- 任一行失败：事务不写入任何样本或业务数据；
- 非预期异常：整批回滚，不保留部分成功数据；
- 同一用户、同一文件摘要和同一幂等键重复请求：返回原处理结果，不重复写入；
- 同一幂等键对应不同文件：拒绝请求并提示重新选择文件。

### 4.4 简单结果反馈

页面不展示复杂导入工作流，只展示一种最终结果：

- 成功：显示实际入库数量和完成时间，立即重新查询清单；
- 失败：显示零入库和错误行数量，提供可下载的错误明细文件；
- 用户修正原文件后可重新上传，系统重新执行同一条自动校验与入库流程。

后台可以保留不可篡改的导入审计记录，但不能把技术处理状态包装成草稿、审核或发布业务流程。

## 5. 删除、并发与权限

### 5.1 删除

删除按钮位于维护清单行级操作中。点击后弹出简短二次确认，说明样本名称及不能删除的常见原因。确认后提交当前权威版本号。

被年度样本网或历史业务记录引用的正式样本继续由后端拒绝删除。删除成功后关闭确认框、重新查询清单并发送业务事件。

### 5.2 并发

编辑页打开时读取最新版本；保存和删除都携带期望版本。发生并发冲突时不覆盖他人结果，页面重新读取最新详情并提示用户重新确认修改。

### 5.3 权限与审计

- 前端按权限隐藏或禁用入口，后端对每次读取和写入继续执行权限及地区范围校验；
- 维护人必须是在岗、账号有效且具有当前地区填报权限的员工；
- 新增、编辑、维护人变更、删除和批量导入都写入操作人、时间、对象、前后版本和结果；
- 权限校验和审计不构成审核流程，不增加用户步骤。

## 6. 实时同步闭环

当前窗口的写操作成功后立即权威重查；其他页面、窗口和登录用户通过业务事件流同步。

受影响范围至少包括：

- 正式样本维护清单和详情；
- 设计样本点清单和详情；
- 当前产品业务台账及最近观测值；
- 总揽样本数量、地图点位和侧栏统计；
- 产情、市场、物流分析及相关报告查询；
- 与样本和期间记录有关的通知数量。

事件刷新必须保留用户当前业务栏目、筛选、页码和返回位置。正在编辑的页面收到同一对象更新事件时，不静默覆盖输入；页面提示数据已变化，并要求重新读取最新版本。事件流断开时显示可恢复状态，不能把旧数据标成最新。

## 7. 真实能力约束

- 不存在静态空壳按钮、模拟上传、前端假成功或只修改内存的数据；
- 所有模板、上传、保存、删除、错误明细和重查都必须有真实后端接口及持久化结果；
- 服务不可用时显示明确不可用状态，不用演示数据替代；
- 页面不显示数据库字段名、内部状态码、内部 ID 或开发过程术语；
- 不引入新的三类台账、草稿箱、审核中心或发布步骤；
- 不把设计样本点写入正式期间事实模型，不把期间记录复制成样本身份。

## 8. 错误处理

前端把服务端稳定错误转换为可操作的业务中文，至少覆盖：

- 字段缺失或格式错误；
- XLSX 格式、表头或文件安全错误；
- 行政区或对象类型无效；
- 坐标超界、超出行政区或已被占用；
- 样本重复或版本冲突；
- 维护人无效；
- 权限或地区范围不足；
- 样本被年度网络或历史记录引用；
- 事件流或权威重查失败。

导入失败必须明确显示“本次零条入库”，防止用户误以为存在部分成功。

## 9. 验收标准

### 9.1 页面

- 当前代码中的 `existing-observation__drawer`、表格旁详情卡和嵌入式样本编辑卡不再承担新增、编辑或期间数据更新；
- 新增、查看、编辑和期间数据更新都有可刷新、可返回的完整页面；
- 期间更新页按服务端返回的对象类型字段定义展示最新适用字段；
- 页面视觉以标题、分区、表单行和表格为主，不出现卡片套卡片；
- 390px、桌面常用宽度和宽屏下无横向溢出、遮挡或不可达操作。

### 9.2 XLSX

- 设计样本点和正式样本点均可下载真实模板并上传真实 XLSX；
- 全部行有效时整批直接持久化，刷新或重新登录后仍可查询；
- 任一行无效时零条入库并能下载逐行错误明细；
- 导入页面不存在草稿、提交审核、批准、发布或二次确认入库；
- 重复请求不会重复创建记录。

### 9.3 实时与数据一致性

- 手工新增、编辑、删除、业务数据更新和 XLSX 导入后，当前页面立即权威重查；
- 业务事件到达后，台账、总揽、地图、统计和分析读取同一权威结果；
- 样本数量在列表、地图和总揽之间一致；
- 历史期间记录不因稳定信息编辑或最新数据更新而被覆盖。

### 9.4 工程与发布 SOP

- Backend 和 Web 分别从当前 `origin/main` 创建边界清晰的功能分支；
- 变更前记录分支、状态和差异，保护其他工作树与用户改动；
- 先完成最小定向回归，再执行两个仓库各自要求的完整门禁；
- 每个仓库形成可恢复提交，推送后创建 PR；
- PR CI 全部通过后才合并，合并后检查对应 `main` CI；
- 本地源码、远端 `main`、构建产物和实际浏览器运行版本分别核验；
- 只有实际浏览器已加载新构建并完成手工新增、编辑、删除保护、业务数据更新、原子导入和实时联动验收，才可声明本阶段闭环；
- 未取得合法发布清单、镜像摘要或运行环境授权时，不伪造部署证据，也不把 PR 合并等同于浏览器已更新。

## 10. 不在本设计中引入

- 三类台账切换；
- 样本或期间数据草稿；
- 人工审核、批准、发布或二次校验；
- 批量修改或批量删除样本；
- 用户可见的内部导入任务状态机；
- 第二套期间事实模型；
- 与本次页面及导入闭环无关的新导航模块。

## 11. 自检

- 独立页面流转与用户已确认的交互一致；
- 删除留在清单二次确认，不制造无意义的删除填报页；
- 对象类型决定期间业务字段，稳定信息与期间事实没有混写；
- 设计样本、正式样本和期间数据的生命周期边界清晰；
- XLSX 是一次自动校验后的整批直接入库，不存在草稿和审核；
- 任一失败零入库，结果可重查、可审计、可实时联动；
- 文档没有静态空壳、模拟数据或提前宣称部署完成。
