# 业务分析报告与导入台账统一设计

日期：2026-08-21
状态：已获业务方确认，进入实施

## 文档状态与后续设计关系

本文继续作为业务分析报告结构、核定数据语义和导入任务台账的权威设计。分析三页的首屏指标呈现，已由同日后续的《产情、市场与供需经营看板视觉重构设计》替代：允许最多六张真实指标卡，但仍必须使用服务端字段、核定来源数和明确缺失状态。本文关于“连续表格式指标带”“不使用独立指标卡”的具体视觉约束不再作为验收条件，其余报告画布、时间轴、缺失不补零和台账要求保持有效。

## 1. 目标

将“导入任务”整理为可持续处理的批次台账；将“产情分析、市场分析、供需平衡”整理为同一套业务分析报告结构。所有数值必须来自已审核、期间已确认的填报记录，由后端核定快照计算；Web 只选择和展示结果，不重新定义业务公式。

## 2. 页面边界

- 导入任务是操作台账，不使用分析仪表盘结构。
- 产情分析、市场分析和供需平衡共享筛选、状态、指标带、趋势图、明细来源的阅读顺序。
- 不增加目标值、健康度、风险分、预测值或现有模板中不存在的业务字段。
- 不把待审、退回、作废和期间未确认的记录计入正式指标。
- 缺失值保持缺失并说明缺少的业务来源，禁止补零。

## 4. 页面业务内容

### 4.1 产情分析

- 核心指标：核定播种面积、预计收获面积、加权预计单产、预计总产、预计收获率、灾损面积占比。
- 月份趋势：播种面积与预计总产分别绘制，不在同一坐标轴混合不同单位。
- 结构区：灾损、质量、成本、补贴保险和下年度意向，只显示当前快照真实存在的指标。
- 明细：调查对象、地区、期间、核定时间。

### 4.2 市场分析

- 核心指标：平均收购价、平均销售价、购销价差、采购量、销售量、当前企业库存。
- 月份趋势：价格趋势与库存趋势分别绘制。
- 结构区：购销活动、流通成本、包装形态与适用质量。
- 明细：市场和物流实际采用记录。

### 4.3 供需平衡

- 核心指标：期初可观测库存、预计总产、物流流入、可观测总供给、可观测总使用、期末可观测库存。
- 主图：供需流向桥，直接展示后端计算结果；任一关键值缺失时保留缺口，不闭合伪等式。
- 趋势：年度各月期末可观测库存；缺失月份显示断点，不进行插值。
- 结构区：生产端与企业端库存分层、主体勾稽、覆盖和缺失来源。
- 明细：本次计算实际采用的产情、市场和物流记录。

## 5. 年度月份序列

Web 对同一产品、地区、年份和可选主体条件读取 1—12 月核定快照。每个图表点直接取服务端快照中的指标值、单位、来源数、质量状态、数据截止和分析版本：

```ts
interface ObservableAnalysisSeriesPoint {
  month: number;
  snapshot: ObservableAnalysisSnapshot;
}
```

Web 不对月份值求和、求平均、换算或补零，只负责选取同一指标码并绘制。查询失败的月份与没有核定数据的月份分开表达；实时业务事件触发当前快照和年度序列重新读取。

## 6. 视觉系统

- `ink #173B58`：标题和正式数值。
- `grain #167D69`：核定、完成和主趋势。
- `sky #2D7EB3`：对比趋势和可交互元素。
- `amber #B6652E`：待修正、覆盖不足和数据缺口。
- `rule #CBDCE7`：表格与报告分隔线。
- `paper #FFFFFF`、`wash #F4F8FA`：报告画布与页面底色。

字体继续使用平台既有中文系统字体，数据采用等宽数字特性。圆角仅保留在按钮和状态标记，不在每个数据块外围重复使用大圆角卡片。

签名元素是“核定数据时间轴”：主趋势图同时表达月份、实际有数据的节点以及缺口，不使用装饰性健康度或预测线。
