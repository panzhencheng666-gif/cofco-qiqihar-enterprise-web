# 齐齐哈尔粮食商情企业平台信息架构重建设计

**状态：** 方案 B 已经用户批准，本文是本轮信息架构与交互视觉实现的规范依据。`CONTEXT.md`、既有领域规格和仓库工程约束继续有效；发生冲突时，领域事实定义以 `CONTEXT.md` 和既有领域规格为准，本轮页面职责与交互以本文为准。

**代码实施边界：** 本轮只改造 `src/prototype` 及其直接测试；除本文和后续实施计划外，不修改仓库中其他用户正在进行的主应用改动。
**目标：** 将现有页面集合收敛为职责清楚、口径一致、可追溯、可扩展的企业级业务平台原型，并建立当前期与前三年同口径比较能力。

## 1. 背景与问题结论

用户指出的八张界面不是相互独立的视觉问题，而是以下系统性问题的结果：

1. 主应用、正式原型和历史设计文档分别存在不同的一级信息架构，平台没有唯一导航真相。
2. 页面以通用模板复用布局，却没有以任务、对象、事实、指标、供需账户和报告划分业务职责，造成总览与名录重复。
3. 地区、人员、期间、报告摘要、供需规则和指标值分散写在不同组件中，形成多套静态真相。
4. 对象类型、业务角色和业务能力被混为一张百科式清单，既不能指导作业，也不能形成有效主数据。
5. 工作责任、单据状态、审核状态、质量状态和发布状态被压成装饰性“当前状态”条，无法支持审计和动作判断。
6. 经营总览依赖卡片堆叠，没有完整业务分类、统一筛选、跨年度比较和可追溯下钻。
7. 报告编制直接采用写死上下文，不能选择业务类型、地区、品种、期间和输入版本。
8. 供需页面展示了明细，却没有明确计算目标、公式、采用结果、调查结果、差额和发布资格。

本设计选择“稳定领域应用＋共享业务内核”。稳定业务导航负责可理解性，共享内核负责一致性；指标、表单、公式和可比规则只在治理层元数据化，不把主业务界面做成万能动态门户。

## 2. 设计原则

### 2.1 一项业务事实只产生一次

任务、对象、总览、供需和报告都是同一业务链的不同投影，不得保存各自的独立业务数字。任何汇总、同比、供需结果和报告指标都引用已核定事实或不可变发布版本。

### 2.2 导航按用户工作目的划分

- “我的工作”回答我现在要处理什么；
- “对象名录”回答我们在监测谁、什么地点或什么设施；
- “任务作业”回答本期要采集、审核或发布什么；
- “分析与报告”回答数据说明了什么；
- “供需核算”回答供给、使用和库存如何勾稽；
- “报表中心”回答如何生成、审核、分发和追踪正式报告。

采集、审核、发布是工作项生命周期，不再作为多个含义相近的孤立页面重复建设。

### 2.3 工作单位和业务地区分离

顶栏只显示当前组织、岗位和授权身份。业务地区、统计地区、对象所在地区是页面查询坐标，由筛选器明确选择。系统不把工作单位名称自动解释为统计地区，也不静默默认齐齐哈尔、玉米或最新版本。

### 2.4 稳定菜单，角色自适应

菜单名称、路由和页面职责保持稳定。角色只决定：

- 可以看到哪些应用；
- 默认进入哪个保存视图；
- 可以查询哪些地区、对象和敏感字段；
- 可以执行哪些填报、审核、发布和导出动作。

### 2.5 表格承载全量，图表解释关系

全量指标和业务记录由筛选台账承载；图表只用于趋势、构成、分布、贡献和地区差异。禁止卡片墙、3D 图、仪表盘、装饰性饼图和无法下钻的孤立大数字。

### 2.6 缺失不是零，不可比不得硬算

真实零、未采集、不适用、拒报、待审核和无正式版本分别表达。基期为零或任一比较坐标不一致时不计算同比百分比，并说明原因。

## 3. 平台信息架构

### 3.1 用户业务面

普通业务和管理用户使用六个稳定应用：

| 一级应用 | 二级结构                                                 | 核心职责                 |
| -------- | -------------------------------------------------------- | ------------------------ |
| 我的工作 | 任务台账；待填报、待审核、异常逾期、待发布、已办保存视图 | 个人动作入口             |
| 经营总览 | 经营态势、异常风险、履责监督、发布成果                   | 管理与决策投影           |
| 产情监测 | 任务作业、对象名录、分析与报告                           | 生产调查全流程           |
| 市场监测 | 任务作业、对象名录、分析与报告                           | 市场主体和物流节点全流程 |
| 供需核算 | 账户计算、区域与年度比较、版本台账                       | 数量账户与勾稽           |
| 报表中心 | 报告编制、审核与分发、报告台账                           | 正式报告生命周期         |

### 3.2 治理管理面

治理和系统管理不挤占普通用户主导航，经应用启动器并按权限进入：

| 管理应用 | 内容                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| 数据治理 | 行政区划、产品、作物、具体品种、对象类型、业务角色、能力模板、指标、单位、公式、可比规则、质量规则、版本血缘 |
| 系统管理 | 组织、账号、岗位、任职、责任、权限、数据范围、系统接入、运行配置和审计                                       |

### 3.3 领域内页面职责

产情和市场领域统一采用三项工作，不统一具体字段：

1. **任务作业**：按本期义务展示对象、业务类型、地区、品种、截止、责任人、单据进度、审核、质量和发布资格。
2. **对象名录**：维护稳定身份、对象类型、有效业务角色、所在地区、经营品类、监测范围、来源渠道和当前有效性。
3. **分析与报告**：消费正式指标版本，提供年度趋势、地区比较、异常解释和发起报告动作。

任务作业和对象名录使用相同对象标识，但不是相同列表：前者是一对象在一个期间的一项工作，后者是跨期间存在的主数据档案。

### 3.4 全局检索、深链接和保存视图

- 全局检索查询当前用户有权查看的对象、工作项、业务单据、异常、报告和发布版本，不再只搜索菜单名称；
- 搜索结果必须标明结果类型、业务域、地区、期间、状态和匹配字段；
- 页面筛选写入可分享的稳定 URL，浏览器前进、后退和刷新不丢失业务坐标；
- 保存视图只保存查询条件、列设置和排序，不复制业务数据；
- 从经营总览、指标或异常下钻到对象和单据后，返回时恢复原筛选和选中项。

## 4. 完整业务分类

### 4.1 产情监测

- 种植生产：播种面积、收获面积、弃收或未收获面积、长势、生育阶段、墒情、病虫害、受灾、成灾、绝收、测产轮次、单产和总产；
- 成本与保障：地租、种子、农药、化肥、灌溉、人工、机耕、现金支出、分摊依据、补贴和保险；
- 余粮与销售：期初库存、入库、销售、损耗、期末库存、销售数量、销售价格、买方、质量和交付；
- 种植意愿：意向面积、品种调整、原因、价格和成本影响；
- 质量调查：水分、容重、杂质、不完善粒、霉变、毒素和适用品种质量项目。

### 4.2 市场监测

- 报价与成交：买卖方向、报价类型、成交价格、数量、币种、税价、包装、交付、结算和有效时间；
- 质量：与报价、交易、库存批次或交付对应的质量条件；
- 库存与仓储：期初、入库、出库、损耗、期末、库点、仓容、批次和库存性质；
- 加工与转化：原料投入、产品产出、副产品、损耗、产线、产能和开机率；
- 直接使用：饲用等终端直接使用数量和依据；
- 销售：产品、规格、销售量、销售价格和客户范围；
- 物流与流向：运输方式、起讫地点、流入、流出、运量、运价、过境和交付；
- 农资：种子、农药、化肥的品种或规格、价格、库存和销量。

### 4.3 供需核算

- 供给：期初库存、本地生产、区域外流入、进口和经规则批准的其他供给；
- 使用与外流：口粮、饲用、种用、加工投入、损耗、区域外流出、出口和经规则批准的其他使用；
- 结果：总供给、总使用、调整前账面期末、批准调整、采用后账面期末、调查期末和平衡差额；
- 辅助指标：输入覆盖率、来源版本、合并抵销、质量状态和发布资格。

### 4.4 报告类型

- 产情监测报告；
- 市场监测报告；
- 供需核算报告；
- 跨业务综合经营分析；
- 履责监督报告；
- 日报、周报、月报、年度报告和专题报告。

## 5. 对象类型、角色和能力的正确位置

### 5.1 对象类型

对象类型是治理主数据，例如行政村、调查片区、农户、家庭农场、田间样方、农技站、贸易商、加工企业、承储企业、批发市场、铁路站点和公路物流节点。行政村台账是来源单据，不是对象类型，归入 `CanonicalDocument` 的来源渠道和凭证关系。

它应当出现于：

- 新建和编辑对象时的必填字段；
- 对象名录的筛选条件和表格列；
- 任务生成规则；
- 对象详情的只读身份摘要。

### 5.2 业务角色

一个对象可以在不同时期承担多个角色，例如米厂同时具有加工、贸易和仓储角色。角色必须带生效区间，不能用一个永久字符串覆盖。

### 5.3 能力模板

能力模板位于数据治理，用于决定该对象类型或角色适用哪些业务单据和字段。主业务页面不再展示百科式“对象业务能力清单”。对象详情只展示当前实际适用能力及其来源模板。

## 6. 共享业务内核

### 6.1 模块边界

| 模块                   | 职责                                                 | 不承担               |
| ---------------------- | ---------------------------------------------------- | -------------------- |
| `OperationalScope`     | 工作单位、身份、授权数据范围、页面业务坐标和保存视图 | 不保存业务事实       |
| `BusinessWork`         | 报送义务、工作项、责任、截止、动作权限和完成轨迹     | 不保存对象主数据     |
| `MonitoringRegistry`   | 对象身份、类型、角色、地区、品类和有效期             | 不保存本期报送状态   |
| `CanonicalDocument`    | 业务单据、原始主张、来源凭证和字段校验               | 不负责跨单据汇总     |
| `QualityReviewRelease` | 质量规则、审核、退回、采用和事实发布                 | 不生成报告文案       |
| `ReleaseCatalog`       | 不可变事实版本、替代关系、截止和血缘                 | 不修改已发布事实     |
| `MetricCatalog`        | 指标定义、公式、单位、聚合、方向性和比较策略         | 不直接渲染页面       |
| `ComparableSeries`     | 当前期与前三年同口径序列、同比和可比性结果           | 不静默转换口径       |
| `SupplyAccount`        | 产品账户计算、调整、调查对账、合并抵销和发布         | 不把价格质量混入数量 |
| `ReportRun`            | 参数校验、输入锁定、预览、送审、发布和导出           | 不在导出时重算指标   |
| `ExecutiveLedger`      | 经营、风险、履责和发布结果的查询投影                 | 不成为业务事实来源   |
| `ExceptionCase`        | 异常发现、指派、解释、复核和关闭                     | 不替代原始记录       |

### 6.2 唯一数据流

```text
组织与责任
  → 报送义务与工作项
  → 业务单据与原始主张
  → 规范事实
  → 事实发布版本
  → 指标发布版本
  → 供需账户发布版本
  → 报告发布版本
```

经营总览、领域分析和报告分别读取上述发布版本，不反向写入业务事实。

## 7. 独立状态模型

系统不再使用一个万能“状态”字符串。至少分开：

- 义务状态：未到期、进行中、按时完成、逾期补填、截止未提交、免报；
- 单据状态：草稿、已提交、已退回、已更正；
- 审核状态：待审核、审核中、通过、退回；
- 质量状态：通过、警告、阻断、待解释；
- 发布状态：未发布、待发布、已发布、已被新版本替代。

### 7.1 合法迁移与动作角色

| 状态维度 | 合法迁移                                                                         | 执行动作                     | 角色与前置条件                                                     |
| -------- | -------------------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------ |
| 义务     | 未到期 → 进行中 → 按时完成；未到期/进行中 → 截止未提交 → 逾期补填；未到期 → 免报 | 开始、完成、确认免报         | 系统按业务日历推进截止状态；责任人完成；授权管理员依据规则免报     |
| 单据     | 草稿 → 已提交；已提交 → 已退回；已退回 → 已更正 → 已提交                         | 保存、提交、退回后更正       | 责任人可编辑；提交前必填校验通过；已提交版本不可原地覆盖           |
| 审核     | 待审核 → 审核中 → 通过或退回；退回后的新提交重新进入待审核                       | 领取、通过、退回             | 授权审核人执行；退回必须有原因；旧提交的审核结论保留               |
| 质量     | 待解释 → 通过/警告/阻断；阻断 → 待解释；警告 → 通过                              | 运行规则、解释、复核         | 规则引擎产生结论；业务人员解释；质量复核人确认                     |
| 发布     | 未发布 → 待发布 → 已发布 → 已被新版本替代                                        | 申请发布、发布、以新版本替代 | 审核通过、无质量阻断、来源版本仍为当前有效版本；发布人具备独立权限 |

### 7.2 跨状态约束

- 质量“阻断”时不得审核通过或发布；
- 质量“警告”必须有解释，是否允许发布由版本化质量规则决定；
- 单据被退回后，旧提交和旧审核记录不删除；新提交形成新的提交版本；
- 审核通过不等于已经发布，发布必须单独执行并记录发布人和时间；
- 上游事实版本被替代时，尚未发布的指标、供需和报告运行立即标记“输入已过期”，禁止发布；
- 已发布结果不回写状态，只能由引用新输入的新发布版本替代；
- 原型展示上述约束和不可执行原因；生产系统必须由服务端重新校验，不信任前端按钮状态。

“责任人、截止和状态”只在任务、单据、审核或发布动作附近展示。对象名录和分析页面不显示通用责任状态条。经营总览的履责情况进入可筛选履责台账。

## 8. 当前期与前三年同口径比较

### 8.1 比较语义

当当前期为 2026 年时，系统读取 2023、2024、2025、2026 四个同口径点，并产生：

- 2024 相对 2023 的同比；
- 2025 相对 2024 的同比；
- 2026 相对 2025 的同比；
- 2026 相对 2023、2024 的直接变化，名称为“较该年变化”；
- 适用时的三年复合增长率。

“与前三年比较”不等于把三个直接变化全部命名为同比。

### 8.2 比较领域模型

`MetricDefinition` 至少包含：

- `metricId`；
- 业务域和业务子类型；
- 数量、金额、价格、比例、百分比或有符号差额等度量类型；
- 公式、标准单位、聚合规则和定义版本；
- 趋势方向语义；
- 比较策略和异常规则版本。

`MetricCoordinate` 至少固定：

- 行政区划及其边界版本；
- 作物、商品、产品形态、产品账户和具体品种；
- 质量、价格和交付条件；
- 对象总体或抽样方案；
- 期间粒度、同周期键和数据截止；
- 正式或初步数据层；
- 输入和指标发布版本。

`PublishedMetricPoint` 保存坐标、值、单位、覆盖率、质量状态和指标发布版本。

`ComparisonSet` 返回：

- `points`：Y-3、Y-2、Y-1、Y 四个点，每个点分别携带 `availability`、`coordinate`、`releaseVersion` 和逐点可用性原因；
- `pairs`：Y-2/Y-3、Y-1/Y-2、Y/Y-1 三个 `ComparisonPair`，每一对分别携带可比结论、绝对变化、同比率和不可比原因；
- `currentVsBaselines`：当前期分别相对 Y-3、Y-2、Y-1 的直接变化，只有 Y/Y-1 命名为当前同比；
- `cagr`：可计算时的三年复合增长率及不可计算原因；
- `trend`：趋势方向、连续性、异常和口径断点。

任何一个历史点不可比，只影响包含该点的比较对，不得屏蔽其他仍然有效的年度比较。

### 8.3 计算、精度与缺失传播

- 权威指标使用定点小数或整数缩放值计算，禁止使用二进制浮点保存正式计算结果；
- `absoluteDelta = current - previous`；
- 对允许计算相对变化且基期为正数的指标，`yoyRate = absoluteDelta / previous × 100%`；
- 对比例或百分比指标，默认返回 `current - previous` 的百分点变化；只有指标定义显式允许时才同时返回相对变化；
- 有符号差额、基期为零或负数的指标不返回同比率，只返回绝对变化和原因；
- CAGR 只在 Y-3 与 Y 均为正数、四个期间等间隔、端点和相邻链均可比时计算，公式为 `(Y / Y-3)^(1/3) - 1`；
- 单位转换在指标发布前按已批准转换规则完成，比较服务不在页面请求时临时换算；
- 任一点缺失、未采集、不适用或无发布版本时，该点保持原缺失语义，相关比较对不产生数值；
- 计算中间值不舍入；展示精度由 `MetricDefinition.displayScale` 指定，最终显示使用十进制 `ROUND_HALF_UP`，导出同时保留未舍入值和显示值；
- 比较服务返回公式、输入点、定义版本和转换版本，使页面、报告和导出可以复核同一结果。

### 8.4 可比性规则

- 产情按同作物年度、同生育阶段或同调查轮次比较；
- 市场按同业务日历期比较，价格必须具有相同币种、税价、质量、形态、交付和计量条件；
- 库存按同统计时点、库存性质和合并矩阵比较；
- 成本按相同费用项、适用面积和分摊规则比较；
- 加工按相同产品转换和折算基准比较；
- 物流按相同边界、方向和运输定义比较；
- 供需按相同产品账户、营销年度阶段、账户规范和合并范围比较；
- 部分年度、周度和月度数据只与历史同一截止日期、同一调查周或同等业务日范围比较，不以本年累计对比历史全年；
- 区域单产使用核定总产量与收获面积推导或采用正式发布值，不计算“县区单产的简单平均”；
- 价格指标必须明确是成交量加权价、报价中位数、主流区间还是其他正式统计量，不把不同统计量放入同一序列；
- 聚合值同时返回覆盖地区、覆盖对象、样本响应和缺失范围，覆盖显著变化时即使数值可算也标记比较风险；
- 基期为零时只显示绝对变化，不显示百分比；
- 比例指标优先显示百分点变化；
- 有符号差额默认显示绝对变化，不使用容易误导的增长率；
- 口径变更只有存在已批准的转换规则版本时才允许桥接，否则明确显示“口径不可比”。

### 8.5 指标范围

凡满足比较条件的指标都进入统一能力，包括：面积、单产、总产、价格、成交量、库存、销量、成本、加工投入、加工产出、副产品、损耗、开机率、物流流入流出、运价、供需构成、期末库存、覆盖率、按时率和质量阻断率。

## 11. 供需核算设计

页面必须首先回答“计算什么、结果是什么、为什么可以或不可以发布”。

```text
总供给 = 期初库存 + 本地生产 + 区域外流入 + 进口 + 其他供给
总使用 = 口粮 + 饲用 + 种用 + 加工投入 + 损耗 + 区域外流出 + 出口 + 其他使用
调整前账面期末 = 总供给 - 总使用
采用后账面期末 = 调整前账面期末 + 批准库存调整
平衡差额 = 调查汇总期末 - 采用后账面期末
```

结果区必须同时显示：

- 带实际数值代入的公式；
- 计算一致性状态；
- 调查对账状态；
- 当前差额及其解释状态；
- 采用来源版本和账户规则版本；
- 发布资格和阻断原因。

容差由版本化账户规则提供，原型不得写死通用阈值。缺少调查值、来源未发布或输入版本失效时，不将缺失视为零。

### 11.1 账户规则选择

系统按 `产品账户 + 地区层级 + 营销年度 + 生效时点` 精确选择一个 `SupplyAccountRuleVersion`。规则至少包含：

- 适用的供给项和使用项；
- 单位、折算、内部流转抵销和合并范围；
- 十进制精度；
- 调查期末是否必需；
- 对账容差的绝对值或比例定义；
- 超出容差时是否允许“批准解释后发布”；
- 接受的数据成熟度和最大来源时效；
- 发布前必须完成的解释和审批角色。

没有匹配规则或同时匹配多个规则属于配置阻断，不得采用任意默认规则。

### 11.2 结果与发布资格判定

| 条件                                       | 计算结论     | 对账结论      | 发布资格                         |
| ------------------------------------------ | ------------ | ------------- | -------------------------------- |
| 任一必需供给或使用项缺失                   | 输入不完整   | 不判定        | 阻断，列出缺失项                 |
| 输入完整但等式按规则精度不成立             | 计算失败     | 不判定        | 阻断，列出公式和差额             |
| 等式成立，规则要求调查值但调查值缺失       | 计算通过     | 无法对账      | 阻断，提示补充调查版本           |
| 等式成立，差额绝对值不超过规则容差         | 计算通过     | 平衡          | 可申请发布                       |
| 差额超容差且解释未提交或待复核             | 计算通过     | 不平衡/待解释 | 阻断                             |
| 差额超容差、解释已批准、规则允许解释后发布 | 计算通过     | 有解释差异    | 带警告可申请发布，锁定解释版本   |
| 差额超容差、规则不允许解释替代平衡         | 计算通过     | 不平衡        | 阻断，必须调整输入或批准账户调整 |
| 任一采用来源已过期、撤销或被重述           | 结果过期     | 原结论失效    | 阻断并重新计算                   |
| 审核未通过或存在质量阻断                   | 保留计算结果 | 保留对账结果  | 阻断                             |

批准库存调整必须是带原因、责任、审核和版本的正式输入。业务解释本身不能偷偷改写差额；需要改变采用后账面期末时，必须形成批准调整记录并重新计算。

## 12. 报告编制设计

### 12.1 参数步骤

报告创建必须允许选择：

- 业务域；
- 报告类型和模板；
- 地区层级与一个或多个授权地区；
- 作物、商品、产品账户和具体品种；
- 日、周、月、年度或专题期间；
- 数据截止；
- 正式或初步数据层；
- 当前期与前三年比较窗口；
- 采用的事实、指标和供需版本；
- 指标、章节和输出格式。

从领域分析发起报告时可以预填当前筛选，但所有参数仍可在授权范围内修改，不得锁死为齐齐哈尔和玉米。

### 12.2 参数依赖与兼容校验

每个 `ReportTemplateVersion` 明确声明适用的业务域、报告类型、频率、地区层级、产品维度、比较窗口、必需指标、可选章节和输入成熟度。参数控件按该契约级联：

- 产情模板只提供作物和具体品种，不提供无关的加工产品账户；
- 市场模板根据业务子类型显示粮食品种或农资商品，并要求对应的价格、质量和交付口径；
- 供需模板必须选择产品账户、营销年度和供需账户版本；
- 履责模板按组织、岗位、地区和责任期间生成，不要求选择粮食品种；
- 跨业务综合报告只能组合具有共同地区边界、共同截止时点和兼容数据成熟度的指标版本；
- 多地区报告只有在模板声明允许聚合且地区边界、单位、指标定义和版本口径一致时生成合计，否则按地区分章展示；
- 具体品种必须属于所选作物或产品，已停用品种只能用于历史报告；
- 所选条件没有可用正式版本时，显示缺少的指标或版本，不回退到初步数据或其他地区；
- 输入版本在预览后被替代时，报告运行标记“输入已过期”，必须重新锁定和生成预览。

参数校验在“生成预览”前执行，并返回字段级错误和跨字段错误；仅改变下拉框而不改变实际查询不视为参数化报告。

### 12.3 生命周期

```text
选择参数 → 校验可用数据 → 锁定输入版本 → 生成预览
→ 保存草稿 → 送审 → 审核通过 → 发布 → 分发/导出
```

正式发布后的修改必须创建新报告运行，保留替代原因和原报告。

## 13. 错误、空状态和异常

系统分别处理：

- 无查看权限；
- 有权限但无数据；
- 没有符合条件的正式发布版本；
- 当前期与历史期口径不兼容；
- 必填供需输入缺失；
- 上游版本已经重述；
- 用户打开页面后数据状态发生冲突；
- 指标、供需或报告异步任务失败；
- 筛选结果为空。

每种状态说明发生了什么、哪些条件受影响、用户可执行什么动作。不得统一显示“暂无数据”或静默回落到默认条件。

异常沿源链闭环：指标异常可以下钻到地区、对象、工作项、单据、规范事实和发布版本，并支持指派、解释、复核和关闭。

## 16. 原型实施边界

本轮原型实现：

1. 收敛 `src/prototype/formalEnterpriseModel.ts` 的应用和二级导航职责；
2. 重构经营总览、产情、市场、供需和报表中心工作区；
3. 新建可独立测试的指标定义、四年可比序列和图表视图模型；
4. 使用类型化原型数据替换报告和总览中的散落硬编码；
5. 为全局搜索提供对象、任务、异常、报告和版本的内存检索结果，并跳转到对应原型页面；
6. 将应用、二级页面和主要筛选写入 URL，提供预置保存视图和会话内筛选恢复；
7. 在应用启动器显示数据治理和系统管理的架构入口、内容范围和权限说明，不实现其详细管理页面；
8. 保留当前原型入口，不改主应用入口和仓库其他用户改动；
9. 不新增重量级图表依赖，使用可访问的 HTML、CSS 和轻量 SVG 表达必要图形；
10. 原型只演示接口和状态，不宣称已经具备真实服务端权限、审计和生产数据持久化。

| 架构能力           | 本轮原型交付                                           | 本轮明确不做                               |
| ------------------ | ------------------------------------------------------ | ------------------------------------------ |
| 六个用户业务应用   | 完整重构页面职责、筛选、台账、分析和关键动作           | 不连接真实后端                             |
| 数据治理、系统管理 | 应用启动器内的只读架构入口、治理范围和权限提示         | 不建设主数据编辑、组织权限配置页面         |
| 全局检索           | 检索类型化内存数据并路由到对象、任务、报告和版本       | 不建设全文索引、拼音分词和服务端相关性排序 |
| 稳定深链接         | 应用、二级页面、地区、产品、期间等主要坐标进入查询参数 | 不实现跨账号分享授权                       |
| 保存视图           | 提供标准视图和当前会话内恢复                           | 不实现服务端个人视图持久化和共享管理       |
| 权限与审计         | 展示授权范围、不可执行原因和审计字段                   | 不宣称前端模拟等同服务端安全控制           |

第 3 章的完整信息架构是生产目标；原型导航验收包括六个业务应用和启动器中的两个治理入口，不要求两个治理应用拥有完整工作页面。

所有演示数据集中在类型化模型或数据夹具中，组件不得内嵌地区、期间、人员、报告结论和指标数值。生产适配器与内存演示适配器遵循相同查询接口。

### 16.1 仓库保护约束

允许发生变化的路径只有：

- `src/prototype/**`；
- 本设计规范；
- 对应的 `docs/superpowers/plans/2026-07-31-*.md` 实施计划。

不修改 `package.json`、主应用、共享组件、领域层、工作流层和平台适配器。实施开始前把仓库状态及允许路径之外的现有修改文件 SHA-256 清单保存到 `/tmp`；每个实施增量结束后重新计算并比较。允许路径之外的文件状态和内容摘要必须与基线完全一致。暂存和提交始终使用显式路径，不使用 `git add .`、`git add -A` 或清理命令，不覆盖、还原或删除用户现有脏文件。

## 17. 稳定性与生产演进要求

生产实现必须具备：

- 一个正式应用入口、一套类型安全路由和一份领域导航定义；
- 服务端能力权限和数据范围双重校验；
- 服务端筛选、排序、分页和异步导出；
- 命令幂等键、强版本号和乐观冲突处理；
- 不可变发布版本、重述链和按截止时点查询；
- 指标、供需、报告异步作业及可重试失败状态；
- 对象、地区、角色、公式和指标定义的生效区间；
- 行级和敏感字段授权；
- 请求、作业、版本和审计关联标识；
- 可配置的性能、可用性、恢复和数据保留目标。

原型不得用前端静态行为伪装这些生产能力已经完成。

## 18. 测试与验收

### 18.1 领域规则测试

- 四个年度点和三段相邻同比计算正确；
- 逐点和逐比较对分别返回可比结论；绝对变化、同比率、百分点变化、显示舍入和 CAGR 符合第 8.3 节；
- 基期为零、负数、缺失、比例、有符号差额、单位转换和单一年度口径不一致分别得到正确且局部传播的结果；
- 面积、单产、产量、价格、库存、加工、物流和供需坐标使用各自可比规则；
- 供需公式、批准调整和调查差额相互独立，并覆盖第 11.2 节全部判定行；
- 五类状态只允许第 7.1 节规定的迁移，跨状态阻断生效；
- 报告输入参数可以更换业务域、地区、品种、期间和版本，无效组合按第 12.2 节拒绝；
- 字段保全测试覆盖第 15 章每一行迁移清单。

### 18.2 页面行为测试

- 一级和二级导航符合第 3 章；
- 全局检索能够区分对象、工作项、异常、报告和版本并保持授权范围；
- 刷新、前进和后退保留应用、二级页面和主要业务坐标；
- 市场和产情的任务作业、对象名录、分析与报告内容不同；
- 市场页面不再出现百科式能力清单；
- 非动作页面不再显示通用责任状态条；
- 经营总览默认“全部授权范围”，具备完整筛选和年度比较；
- 报告编制器没有写死齐齐哈尔、玉米和固定报告类型；
- 供需页面明确显示代入公式、结论、差额和发布资格；
- 所有原有有效字段能够在正确工作区找到。

### 18.3 视觉验收

- 1280、1440 和 1920 像素桌面视口无布局破坏；
- 1024 像素可通过折叠筛选和表格滚动完成核心操作；
- 图表、表格和抽屉选择联动；
- 页面不形成卡片墙；
- 数字、单位、正负变化、缺失和不可比状态清楚；
- 键盘焦点可见，重要状态不只依赖颜色；
- 语义前景色与背景达到 WCAG AA，金色和浅青不作为白底普通正文；
- 经营总览、供需结果、报告参数和两个领域的任务/对象差异通过浏览器截图复核。

### 18.4 仓库隔离验收

- 实施前后的 `/tmp` 状态和 SHA-256 基线比较无差异；
- `git diff --name-only` 中本轮新增变化只属于第 16.1 节允许路径；
- 每次暂存后的 `git diff --cached --name-only` 只包含该增量声明的文件；
- 仓库既有脏文件没有被格式化、覆盖、还原、暂存或删除。

## 19. 实施顺序

实现拆成可独立验收的六个垂直增量：

1. 导航、页面职责和业务坐标；
2. 指标定义、四年可比序列和年度比较轨道；
3. 经营总览趋势台账；
4. 产情与市场的任务、对象、分析分离；
5. 供需公式结果、比较和版本台账；
6. 参数化报告、审核分发、报告台账和整体视觉验收。

每个增量先写失败测试，再完成最小实现，再运行相关测试；全部完成后运行原型测试、类型检查、构建和浏览器视觉验证。
