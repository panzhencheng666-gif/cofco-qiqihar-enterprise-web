# 现有样本点淘汰确认抽屉设计

## 目标

将市场、产情现有样本点台账中的“淘汰为历史”入口改为专用确认抽屉。现有台账必须完整保留在背景中，不新增历史样本点台账，也不改变总揽地图架构。

## 界面

- 抽屉沿用现有企业台账的 540px 右侧抽屉、蓝色标题栏、直角控件和表格密度。
- 标题为“淘汰现有样本点”。
- 展示样本点名称、地区/品种/现有样本点身份、坐标、维护人和历史归档年度。
- 展示明确警告：淘汰会将点位移出当前样本，但保留最后一次维护数据并进入历史样本；不是物理删除。
- 抽屉仅提供“返回台账”和“确认淘汰该样本点”两个业务操作。
- 不展示编辑、改派维护人、物理删除、版本、年度观测数量或样本网引用等无关操作和字段。

## 数据闭环

- 确认操作继续调用 `retireFormalSamplePoint(id, expectedVersion, reason)`，使用统一审计原因“现有样本点不再使用，由维护人在业务台账执行淘汰”。
- 成功后关闭抽屉、重新查询当前台账、触发既有 `onChanged` 联动，并返回台账路由。
- 后端既有 `FORMAL_SAMPLE_POINT_RETIRED` 事件负责刷新总揽当前/历史图层及相关分析；本阶段不新建第二套同步模型。
- 失败时保留既有权限、地区、版本冲突和不存在错误提示；版本冲突后重新查询权威数据。

## 验收

- 市场和产情台账的“淘汰为历史”直接进入专用抽屉。
- 背景台账仍可见，抽屉内只有两个业务按钮。
- 不执行真实业务样本淘汰；使用组件测试证明 API 参数、重查、关闭和联动回调。
- 通过聚焦测试、格式/类型检查和生产构建后，按 PR CI、main CI、真实 63182 浏览器验收发布。
