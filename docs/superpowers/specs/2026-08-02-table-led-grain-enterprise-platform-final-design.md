# 齐齐哈尔粮食商情企业平台表格主导式最终整改设计

日期：2026-08-02

状态：最终效果方向已获用户批准，等待书面规范复核

实施边界：本轮实现仅修改 `src/prototype/**` 及其直接测试；本设计文件和后续实施计划
除外。仓库中其他用户改动保持原样，不暂存、不提交、不覆盖。

## 1. 决策摘要

平台统一采用“稳定企业框架、业务树、紧凑查询、标准宽表、按需详情”的架构。

本轮不是继续修补已有页面，而是把全套原型收敛为一套长期运营型系统：

1. 顶部承担平台级应用切换、全局搜索、待办、通知、帮助、设置和个人中心；
2. 左侧只显示当前应用的业务目录，产品由菜单确定，内容区不再重复选择产品；
3. 业务内容以列表、台账、单据和标准表格为主体，删除驾驶舱卡片墙；
4. 地区通过分级选择器表达，不再用一个超长下拉框混放地市、区县、乡镇和行政村；
5. 产情、市场、物流、供需和报告各自承担唯一职责，不建立内容相同的重复页面；
6. 对象详情仅在用户点击后打开，复杂填报按业务章节分区，不把全部字段同时平铺；
7. 供需平衡由已核定业务数据自动计算，主表明确展示公式结果、来源和状态；
8. 当前期与前三年同口径数据形成四年序列、逐年同比和趋势图；
9. 全部业务界面使用中文业务语言，不暴露内部编码、开发版本或技术实现术语；
10. 已存在的有效业务字段全部保留，只改变信息组织、入口和展示方式。

本设计取代此前规格中与下列内容冲突的部分：卡片化工作台、重复页面、平铺能力清单、
超长地区下拉、技术版本字段、万能状态条、永久侧栏详情和产品重复筛选。既有领域规格中
关于业务字段、审核、发布、血缘、责任和数据口径的有效定义继续保留。

## 2. 方案选择与参考体系

### 2.1 已比较方案

| 方案 | 特点 | 结论 |
| --- | --- | --- |
| 卡片驾驶舱继续优化 | 保留现有页面骨架，只调整卡片、筛选和说明 | 无法消除重复与职责不清，不采用 |
| 传统宽表系统原样复刻 | 深色业务树、密集查询、超宽编辑表 | 操作直接，但容易产生过深菜单和老旧交互，不原样采用 |
| 企业业务树加现代标准表格 | 继承现网系统的直接性，融合列表、详情、分区表单和审计能力 | 采用 |

### 2.2 参考体系的实际落点

本设计不是复制某一套皮肤，而是融合以下成熟结构：

- 现网长期运行系统：业务树、紧凑查询、批量表格、直接操作；
- SAP Fiori：列表工作台、对象详情、列表到详情的稳定联动；
- Microsoft 企业应用：角色视图、保存筛选、表单页签和逻辑分区；
- Oracle Redwood：章节、展开区块、附件和变更记录；
- Salesforce 与 ServiceNow：行级操作、状态工作队列和可配置列表。

最终页面第一眼必须说明“这是什么表、查什么范围、哪些数据缺失、下一步做什么”，
而不是展示架构名词、原则说明或装饰性指标。

## 3. 设计目标与非目标

### 3.1 设计目标

普通业务人员进入任一页面后五秒内应当识别：

1. 当前应用和具体业务；
2. 当前产品、地区和期间；
3. 主表每一行代表什么对象或数据；
4. 黄色可编辑单元格需要填什么；
5. 数据是待填、待审、需补充还是已核定；
6. 可以查询、保存、导入、校验、提交、审核或下钻哪一项。

平台同时满足：

- 信息密度高但不杂乱；
- 业务功能完整但不重复；
- 主导航、左侧菜单、内容区和详情层职责稳定；
- 1920px 和 1440px 桌面宽度下保持完整企业工作台；
- 1280px 下通过表格内部横向滚动完成核心操作；
- 业务事实、审核、发布、供需和报告全程可追溯。

### 3.2 非目标

- 不建设装饰性驾驶舱；
- 不把所有指标都变成图表；
- 不复制参考系统的菜单名称、水印、颜色或过深业务树；
- 不在原型界面展示接口名、内部编号、代码版本、模型名或实现状态；
- 不通过删字段来获得简洁；
- 不改造 `src/prototype/**` 以外的用户工作。

## 4. 全局信息架构

### 4.1 一级应用

顶部一级应用固定为：

```text
我的工作｜经营总览｜产情监测｜市场监测｜供需分析｜报表中心
```

“物流节点监测”属于市场监测的业务类型，只在市场监测左侧目录出现一次，不再同时
作为顶部独立应用，避免一个业务出现两个入口。

治理和系统管理不挤占普通用户一级导航：

- 有权限的管理员通过右上角“设置”进入系统管理；
- 数据治理从设置中的“业务基础数据”进入；
- 普通业务人员看不到无权使用的管理入口。

### 4.2 顶部平台栏

顶部平台栏从左到右为：

```text
平台标识与名称
→ 一级应用
→ 全局搜索
→ 待办
→ 通知
→ 帮助
→ 管理员设置（按权限显示）
→ 头像与个人中心
```

全局搜索支持地区、企业、调查对象、物流节点、任务和报告。结果必须显示结果类型、
所属业务、地区和状态，不能只匹配菜单名称。

待办显示待填报、待审核、退回补充、待发布等当前用户动作。通知显示业务提醒、审核
结果、质量异常和报告发布结果。帮助包含操作说明、指标口径、填报规范和问题反馈。

头像菜单包含：

- 个人资料；
- 当前组织、岗位和责任范围；
- 代理与工作交接；
- 常用条件与显示偏好；
- 账号安全与登录设备；
- 切换账号和退出登录。

账号、退出、个人资料和偏好不单独平铺为多个顶部按钮。

### 4.3 左侧业务目录

左侧业务目录默认展开，显示当前一级应用内部的工作流程。目录不承载地区树，不复制
平台名称和组织信息，最多两层。

#### 我的工作

```text
待我处理
待我填报
待我审核
退回与异常
已办事项
```

#### 经营总览

```text
经营运行
风险事项
履责监督
发布成果
```

经营总览采用筛选台账和趋势分析，不使用卡片驾驶舱。

#### 产情监测

```text
玉米产情填报
大豆产情填报
水稻产情填报
产情任务
调查对象
数据审核
产情分析
```

#### 市场监测

```text
玉米市场采集
大豆市场采集
稻谷市场采集
物流节点监测
采集任务
监测对象
数据审核
市场分析
```

菜单不使用“日报”等直接照搬参考系统的名称。产品选中后，内容区不再重复显示产品
选择器；仅在必要时筛选具体品种、产品形态或质量等级。

#### 供需分析

```text
玉米供需平衡
大豆供需平衡
稻谷供需平衡
计算记录
```

#### 报表中心

```text
业务报告
综合报告
报告审核与发布
报告台账
```

报告频率是生成参数，不展开成大量相似菜单。

## 5. 地区、组织和权限

### 5.1 三个概念分离

- 工作组织：用户当前所属经营部、部门或粮库；
- 责任范围：当前岗位被授权管理的数据范围；
- 业务地区：当前查询、填报或统计的地理范围。

界面不得将三者合并为“全部授权范围”一个含混选择，也不得默认把工作组织解释为业务
地区。

### 5.2 地区层级

平台业务范围为：齐齐哈尔市全域、黑河市全域、呼伦贝尔市指定范围。页面按业务需要
逐级选择：

```text
省／自治区
→ 地级市／盟
→ 区、县、旗、县级市
→ 乡、镇、苏木、街道
→ 行政村、嘎查
```

规则：

- 市场主体和物流节点通常选择到区县；需要精确位置时在详情中记录乡镇和地址；
- 产情任务允许逐级选择到乡镇和行政村；
- 供需正式账户以市域或区县为计算范围，不用行政村做产品账户；
- 每一级只展示所选上级下的有效子级；
- 不使用包含几十个不同层级地区的单一长下拉；
- “同义镇调查片区”“样本户组”等未经业务确认的伪对象名称全部删除。

任务名称使用可理解结构：

```text
期间 + 地区 + 产品／作物 + 明确业务动作
```

例如“2026年第31周讷河市玉米产情调查”。调查对象显示真实农户、合作社、家庭农场、
农技机构或行政村名称。

## 6. 统一页面骨架

### 6.1 清单与填报工作台

产情、市场、物流、任务、审核、供需和报告台账统一采用：

```text
面包屑
→ 紧凑查询区
→ 居中的业务表名称和当前范围
→ 表格工具栏
→ 标准业务表格
→ 合计、问题数量和分页
```

查询条件通常为 4–6 个。默认显示最常用条件，其余条件放入“更多条件”，不允许在首屏
平铺十个以上选择器。

### 6.2 标准表格

标准业务表格遵循：

- 主内容区直接承载表格，不用卡片包裹表格；
- 蓝色分组表头，复杂指标使用两层表头；
- 清晰行列边界；
- 冻结序号、对象名称和关键识别列；
- 表头固定，宽表仅在表格区域横向滚动；
- 可编辑单元格使用浅黄色背景；
- 必填、错误和异常显示在对应单元格或行，不集中成一块无法定位的说明；
- 状态列使用中文业务状态；
- 操作列保留查看、填报、审核、追溯等明确文字；
- 支持列设置、列宽调整、排序、批量导入、校验和导出；
- 页脚展示记录总数、完整性、异常数、合计和分页。

不得使用过小字体、彩色水印、每行重复的插入／删除大按钮或装饰性图标。

### 6.3 对象详情

对象详情默认不占用永久右侧空间。用户点击表格“查看”后进入独立详情或可关闭详情层，
并保留原列表的筛选、分页和选中行。

详情采用：

```text
对象标题与状态
→ 身份与业务角色
→ 当前业务数据
→ 质量与审核
→ 附件与来源凭证
→ 变更和历史记录
```

对象类型出现在对象维护必填项、名录筛选、表格列和详情身份区。对象能力模板只在数据
治理中配置；业务界面不再平铺“业务对象能力清单”。

### 6.4 复杂业务单据

复杂产情和市场单据使用页签、章节和可展开区块：

- 只展示当前对象和业务类型适用的字段；
- 不适用字段直接隐藏，不显示大量“本单据不适用”；
- 责任确认在单据或章节层完成，不在每个字段下重复“责任人已确认”；
- 附件、来源、校验、审核意见和变更历史独立成章；
- 用户离开未保存页面时必须提示；
- 保存草稿、提交审核、退回修改和重新提交形成可追溯记录。

## 7. 业务模块设计

### 7.1 产情监测

玉米、大豆和水稻分别从左侧菜单进入，页面不再重复选择作物。具体品种仍是查询或填报
字段。

产情调查表按需要覆盖：

- 种植与面积：播种、收获、未收获、受灾、成灾、绝收；
- 长势与灾情：长势指数、生育期、墒情、病虫害和灾情；
- 单产与总产：区域加权单产、样本平均单产、预计单产和总产；
- 质量：水分、容重、杂质、不完善粒、霉变粒、毒素等适用指标；
- 余粮与销售：库存、销售、自用、损耗、价格、买方和交付；
- 种植意愿：下一年度意向面积、调整原因和具体品种变化；
- 成本与保障：地租、种子、农药、化肥、灌溉、人工、机耕、其他成本、补贴和保险。

主列表只显示完成任务所需的关键列。完整字段按章节进入对象单据，不能因为主表列数少而
删除任何有效字段。

### 7.2 市场监测

玉米、大豆和稻谷分别进入采集表。市场对象类型决定适用字段，但不会形成多个内容相同
的页面。

对象类型覆盖：

- 贸易商；
- 玉米深加工企业；
- 大豆压榨、大豆蛋白加工、食品与调味品企业；
- 米厂；
- 饲料和养殖企业；
- 承储企业和储备库；
- 批发市场；
- 种子、农药和化肥经销商。

市场事实覆盖报价、成交、质量、库存、加工、销售、直接使用和农资。价格必须绑定产品、
具体品种、质量、数量、单位、包装、交货方式、方向、有效时间和结算条件。

### 7.3 物流节点监测

物流节点不再隐藏在市场主体能力清单中，作为市场监测的明确工作入口。节点类型包括：

- 铁路站点；
- 公路物流节点；
- 港口及装卸点。

物流监测表显示节点、地区、流入量、流出量、运输方向、运价、时效、责任人和状态。
物流事实进入供需账户前必须经过校验、审核和采用。

### 7.4 供需平衡

供需主表首先明确计算目标，而不是只展示一组来源数字。结果区显示：

```text
总供给
总使用
计算期末库存
核定调整
核定期末库存
调查期末库存
账面差异
```

计算公式为：

```text
总供给 = 期初库存 + 本地生产 + 区域外流入 + 进口 + 其他供给
总使用 = 口粮 + 饲用 + 种用 + 加工投入 + 损耗 + 区域外流出 + 出口 + 其他使用
计算期末库存 = 总供给 - 总使用
核定期末库存 = 计算期末库存 + 核定调整
账面差异 = 核定期末库存 - 调查期末库存
```

来源映射：

- 上年度正式期末库存进入本期期初库存；
- 产情已核定总产进入本地生产；
- 物流已核定流入和流出进入区域外流入、区域外流出；
- 市场已核定库存、加工、饲用、销售和进出口进入对应项目；
- 价格、质量、成本和种植意愿是解释因素，不直接与数量相加。

计算状态：

1. 草稿数据变化后实时更新“试算结果”；
2. 上游业务审核通过后进入正式候选输入；
3. 所有必需来源通过审核且无质量阻断后生成正式结果；
4. 已生成的正式结果不被后续草稿静默覆盖；
5. 核定调整只能由授权人员执行，必须填写原因；
6. 每个项目都能查看来源记录、审核状态和计算记录。

主界面不显示内部来源编号或技术版本代码。需要追溯时使用中文来源名称、业务期间、
核定时间和审核人。

### 7.5 报表中心

报告生成不再写死业务、地区、产品和具体品种。新建报告时必须选择：

- 报告类型：产情、市场、物流、供需、综合经营或履责；
- 地区范围；
- 产品或作物；
- 具体品种（适用时）；
- 报告期间和频率；
- 数据截止时间；
- 采用的已核定数据；
- 报告章节和接收范围。

报告编制顺序为：选择参数、校验可用数据、生成预览、编辑说明、送审、发布和导出。
日报、周报、月报和年度报告是参数，不复制成多个内容相同页面。

报告内容、导出文件名和界面只使用中文业务名称。内部运行编号留在系统内部，业务人员
无需理解。

### 7.6 经营总览与我的工作

经营总览使用统一筛选和连续台账，不使用一组默认齐齐哈尔且不可筛选的卡片。筛选覆盖
业务域、地区、期间、产品／作物、具体品种和风险状态。结果通过经营趋势、风险事项、
履责监督和发布成果四个表格视图组织。

我的工作不显示意义不明的“责任岗位有效”状态条。当前组织、岗位和责任范围位于个人
中心；页面主体是按截止时间和风险排序的工作队列。

## 8. 当前期与前三年比较

### 8.1 比较规则

当前期为 2026 年时，读取 2023、2024、2025 和 2026 四个同口径值，计算：

- 2024 相对 2023 的同比；
- 2025 相对 2024 的同比；
- 2026 相对 2025 的同比；
- 当前期相对前三年各年的直接变化；
- 适用时的三年复合增长率。

只有地区边界、产品、具体品种、质量与价格条件、对象总体、期间粒度、单位和数据层一致
时才允许计算同比。缺失不是零；基期为零或口径变化时显示原因，不强行给出百分比。

### 8.2 适用指标

可比指标包括但不限于：

- 产情：播种、收获、未收获、受灾、成灾和绝收面积，单产、总产和长势；
- 市场：采购价、成交价、成交量、库存、加工投入、产品产出、开机率和销售量；
- 物流：流入量、流出量、运价和时效；
- 供需：总供给、总使用、各分项使用、期末库存和账面差异；
- 履责与质量：报送覆盖率、按时率和质量阻断率。

### 8.3 展示位置

- 产情分析：面积、单产、总产和质量四年趋势；
- 市场分析：价格、交易、库存和加工四年趋势；
- 物流分析：流入、流出、运价和时效趋势；
- 供需平衡：本期、上期和四年趋势联动；
- 经营总览：经筛选后的关键指标趋势，不做固定卡片；
- 报告预览：按所选章节插入趋势图和同比表。

图表采用折线、分组柱形或组合图，并始终附带可核对的年度明细表。图表不替代业务主表，
不使用 3D、仪表盘或装饰性饼图。

## 9. 状态、错误和空数据

状态分为：

- 任务状态：待开始、进行中、已提交、退回补充、已完成、逾期；
- 审核状态：待审核、审核中、通过、退回；
- 质量状态：待校验、通过、警告、阻断；
- 采用状态：未采用、候选、已核定、已被替代；
- 报告状态：草稿、待审核、已发布、已撤回。

不得用一个“状态”代替所有维度。列表只显示当前动作最相关的状态，详情显示完整轨迹。

错误处理：

- 必填缺失、格式错误和口径冲突定位到单元格；
- 批量导入先预检，给出成功、警告和失败行，不覆盖有效数据；
- 保存失败保留用户已编辑内容并允许重试；
- 提交时服务端规则再次校验，不信任前端按钮；
- 上游数据被替代时，未发布的供需和报告标记输入已变化并禁止发布；
- 无权限操作不显示或明确说明原因；
- 无数据时说明当前范围没有记录、尚未采集或尚未核定，不能显示为零。

## 10. 中文业务显示策略

操作界面禁止显示：

- `METRIC-2026-W31-V3` 等内部编码；
- “指标数据版本”“采用版本”“数据层”等开发或治理术语；
- 组件名、接口名、模型名、代码提交或环境名称；
- “对象能力清单”“工作项生命周期”等设计术语；
- 未经确认的“调查片区”“样本户组”等伪业务对象；
- 每个字段下重复的“责任人已确认”；
- 大量“本单据不适用”。

需要表达数据可信度时，使用业务人员能理解的中文：已核定数据、数据截止、审核通过、
来源业务、核定时间、责任人和审核人。

## 11. 组件与代码边界

原型实现应拆分为可独立理解的单元：

- `EnterpriseShell`：顶部平台栏、一级应用和个人中心；
- `BusinessNavigationTree`：当前应用业务目录；
- `CompactQueryBar`：页面查询和保存条件；
- `EnterpriseWorkTable`：分组表头、冻结列、编辑、状态和分页；
- `RegionCascadeSelector`：逐级地区选择；
- `ObjectDetailWorkspace`：对象详情、来源、附件和历史；
- `BusinessDocumentWorkspace`：复杂单据章节和校验；
- `AnnualComparisonWorkspace`：四年趋势、同比和可比性说明；
- `SupplyBalanceLedger`：供需公式、输入、结果和计算记录；
- `ReportComposer`：动态参数、预览、审核和导出。

共享组件只统一布局和交互，不把不同业务字段强行合并为一份万能配置。产品、地区、期间、
状态和业务事实必须由同一领域模型派生，不能在多个页面分别写死。

## 12. 验收与测试

### 12.1 结构验收

- 六个一级应用职责唯一；
- 物流节点监测只在市场监测出现一次；
- 玉米、大豆、水稻／稻谷分别有明确入口；
- 内容区不重复显示已经由菜单确定的产品；
- 地区可以逐级选择到适用层级；
- 顶部具备搜索、待办、通知、帮助、设置和个人中心；
- 普通业务人员看不到无权使用的系统设置。

### 12.2 业务验收

- 产情有效字段完整保留并按章节组织；
- 市场主体、加工、储备、农资和物流字段完整保留；
- 物流节点入口和数据表可独立操作；
- 供需结果按已核定来源自动计算，草稿和正式结果分离；
- 报告可以选择业务、地区、产品、具体品种、期间和数据截止；
- 可比较指标具有当前期与前三年数据、逐年同比和趋势图；
- 每一供需项目、指标和报告可以追溯中文业务来源。

### 12.3 视觉与交互验收

- 主工作区不出现驾驶舱卡片墙；
- 表格具有分组表头、明确网格、黄色编辑单元格和直接操作；
- 1920px 与 1440px 显示完整左侧目录和主工作区；
- 1280px 宽表只在表格内部横向滚动；
- 详情只在点击后出现，关闭后恢复原列表状态；
- 查询条件、表格、分页和详情键盘可操作；
- 中文文本不被截断到无法理解。

### 12.4 自动化测试

- 单元测试：地区级联、字段适用性、同比与可比性、供需公式、报告参数；
- 组件测试：菜单选中、产品上下文、查询条件、表格编辑、详情打开与关闭；
- 业务流程测试：填报、校验、提交、审核、采用、供需计算、报告生成；
- 字段保全测试：整改前全部有效业务字段仍能通过相应单据或详情访问；
- 文案扫描：业务页面不得出现内部编码和禁止术语；
- 视觉回归：桌面端关键页面截图与已批准的最终结构一致；
- 原型完整测试和构建必须通过。

## 13. 实施顺序

实现按下列依赖顺序推进：

1. 统一显示策略、产品上下文和地区级联；
2. 顶部平台栏、个人中心和左侧业务目录；
3. 紧凑查询与标准企业表格；
4. 玉米、大豆、水稻／稻谷的产情和市场工作台；
5. 物流节点监测；
6. 对象详情和复杂业务单据；
7. 供需自动计算、正式结果和来源追溯；
8. 报告动态参数与报告台账；
9. 四年趋势、同比和经营总览台账；
10. 全量文案、字段保全、视觉回归和构建验证。

每一阶段必须保持原型可运行，完成对应测试后再进入下一阶段。
