# 市场、产情、物流现有样本列表维护设计

## 目标

在市场、产情、物流原有业务列表中完成样本维护和业务数据填报，不再建立独立的“采集台账”界面。保留当前页面架构、筛选区位置、表格风格和导航方式，只调整必要的筛选项、列表字段和行操作。

## 业务边界

样本稳定信息与期间业务数据继续分开保存：

- 样本稳定信息包括样本名称、地区、详细地址、对象类型和当前维护人。
- 期间业务数据包括价格、库存、采购量、销售量、生产量及其他按市场、产情、物流领域定义的字段。
- 每个样本点同一时间只有一名当前维护人，一个账号可以负责多个样本点。
- 当前维护人必须是实际填报人。期间记录以登录账号作为填报人，不允许通过下拉框冒用其他账号身份。
- 新增样本或由授权管理员调整责任时，从在岗且具备对应地区权限的账号中选择维护人。
- 每条期间记录保存实际操作账号及当时的维护责任快照，后续改派不得改写历史记录。

## 页面与列表

市场、产情、物流现有页面保持当前布局和视觉结构，不增加新的顶级页面、卡片或工作流。

三类列表统一执行以下调整：

- 删除“填报状态”筛选框及其查询参数、前端状态和测试契约。
- 列表新增“详细地址”和“样本点维护人”两列。
- 保留“查看记录”。
- 彻底移除“查看照片”操作，不保留空按钮或替代入口。
- 操作列新增“编辑”和“删除”。
- “编辑”打开该业务页面原有的期间数据表单；有当前期间记录时更新，无记录时创建。表单维护价格、库存等业务字段，不另建样本采集页面。
- “删除”针对样本主体，不解释为删除单条期间记录。
- 市场类对象类型必须包含“农资店”，使用权威对象类型编码 `AGRICULTURAL_INPUT_STORE`，不得在页面写死另一套枚举。

独立“采集台账”入口、页面和相关路由退出用户导航。原有市场、产情、物流入口直接呈现各自业务列表。

## 权限与账号责任

样本维护责任以服务端关系为权威，账号与授权页面展示账号负责的样本点；样本列表展示同一关系的反向视图。两处不各自保存副本。

- 授权管理员可以新增样本、删除符合条件的样本、指定或改派维护人。
- 当前维护人可以填写和编辑自己负责样本的期间业务数据。
- 非维护人即使具有同地区普通填报权限，也不能修改该样本数据。
- 改派必须记录原维护人、新维护人、操作者、原因和时间，并通过实时事件刷新业务列表。
- 账号停用或失去地区权限后，不再允许继续填报；管理员必须先改派后续维护责任。
- 吴雨桐账号当前仅在本地候选验收阶段保留全权限，用于完成端到端验证。
- 正式部署前必须取消吴雨桐的特权授权，再用正式角色完成管理员、维护人、非维护人三类权限验收。未通过该门槛不得声明正式上线完成。

## 删除规则

删除采用受保护的样本主体删除：

- 没有期间历史且未被年度样本网引用的样本可以删除。
- 已有任何市场、产情或物流历史，或仍被年度样本网引用的样本禁止直接删除，并显示明确业务原因。
- 删除使用版本条件避免并发覆盖，同时记录审计事件并发送实时事件。
- 不级联静默删除历史业务记录，不通过隐藏或停用冒充删除成功。

## 移除的功能

市场、产情、物流页面移除以下可见功能及不再使用的前端编排状态：

- 下载退回记录修正表。
- 批量导入退回修正结果。
- 导入修正结果及错误明细入口。
- 与上述入口专用的 loading、job、message 和文件选择状态。

普通业务数据导入是否保留按现有页面能力处理；本设计只删除“退回修正”链路，不把正常导入一并删除。

## 数据流

列表查询返回样本稳定信息、当前维护责任及当前筛选期间的业务记录摘要。页面不通过多次客户端拼接形成互相矛盾的维护人或地址。

1. 用户进入原有市场、产情或物流页面。
2. 服务端按领域、产品、地区和期间返回授权样本列表。
3. 当前维护人点击“编辑”，提交该样本当前期间业务数据。
4. 服务端校验登录账号就是当前维护人，并保存业务记录、审计和实时事件。
5. 所有打开的相关列表通过实时事件重新查询权威数据。

## 总揽监测联动

- 市场、产情或物流业务数据更新并达到总揽当前采用的生效条件后，总揽监测必须通过业务事件重新查询权威投影，显示最新价格、库存等数据；不得依赖刷新页面或客户端缓存拼接。
- 联动规则适用于任意合法的新旧数值，不绑定某个示例金额。
- 未通过当前生效条件的数据继续按现有总揽口径排除，本功能不绕过审核或有效期规则。
- 正式样本的名称、地区、地址、坐标、对象类型或维护责任变化后，总揽中的对应样本信息同步刷新。
- 设计样本点只同步自己的名称、地区、地址、坐标、对象类型等参考信息。设计样本不自动继承或复制正式样本的价格、库存等期间业务数据；只有转为正式样本并产生符合总揽口径的业务记录后，才进入正式业务指标。
- 总揽地图、数量、侧栏、列表、详情和分类筛选必须读取同一权威结果，不能只更新其中一个表面。

## 错误处理

- 维护责任缺失：提示管理员先在账号与授权中指定维护人。
- 非维护人编辑：明确提示当前账号不是该样本维护人。
- 维护人账号失效或地区权限不匹配：阻止填报并要求改派。
- 删除存在历史或年度引用的样本：保持数据不变并显示具体阻塞原因。
- 版本冲突：重新查询后提示用户基于最新数据操作。

## 验收范围

先运行最小相关测试，再由仓库完整 CI 承担全量门禁：

- 市场、产情、物流列表不再出现填报状态筛选和查看照片。
- 三类列表显示详细地址、维护人、查看记录、编辑和删除。
- 市场对象类型能筛选和显示农资店。
- 当前维护人可创建和更新期间数据，非维护人被拒绝。
- 无历史样本可删除；有历史或年度引用样本不能删除且无副作用。
- 改派后列表通过实时事件刷新，历史填报人不被改写。
- 账号与授权页面和业务列表显示同一维护责任。
- 任一总揽采用字段更新后，已打开的总揽页面通过实时事件重查并显示最新已生效值；刷新后结果保持一致。
- 正式样本稳定信息变化同步到总揽各表面，设计样本只同步参考信息且不出现伪造业务价格或库存。
- 桌面和 390px 宽度保持现有页面结构且无页面级横向溢出。
- 正式部署前验证吴雨桐特权已取消，并完成管理员、维护人、非维护人权限矩阵。

## 发布边界

本设计的代码、PR CI、主干 CI、本地运行和浏览器验收分别记录。完成本地候选验收不等于正式部署；只有取消验收特权、生成正式发布清单并通过正式环境权限与数据验证后，才能进入正式上线结论。
