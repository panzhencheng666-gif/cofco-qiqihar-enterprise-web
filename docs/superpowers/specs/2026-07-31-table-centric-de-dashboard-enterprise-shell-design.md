# 表格主导式去驾驶舱化企业框架设计

日期：2026-07-31

状态：用户已确认设计方向，等待书面规格复核

适用范围：齐齐哈尔粮食商情企业平台六大业务应用及其全部演示页面

## 1. 决策摘要

全系统采用“深色 L 形企业框架、表格主导式业务工作台、分级图标体系”。

本轮不是减少业务功能，而是重建信息组织方式：

1. 平台顶部和左侧形成稳定、连续的深色 L 形框架；
2. 内容区取消驾驶舱卡片网格、模块方块和重复上下文；
3. 产情、市场、供需、报表和履责页面以连续工作流和主表格为中心；
4. 数据填报继续位于所属业务内部，不拆成独立、孤立的业务应用；
5. 玉米、大豆、稻谷的品种、价格、质量、数量、库存、加工和物流字段完整保留；
6. 图标辅助识别，但关键业务动作始终保留文字；
7. 经营总览只保留必要的管理摘要，不扩展为卡片驾驶舱；
8. 页面不得出现开发语言、演示版本组合、组件名称或人工智能生成痕迹。

设计参考企业系统截图的框架优点，但不复制其过深菜单、重复分类、过小字体和
蓝绿按钮堆叠。

本设计只重定全系统的视觉框架、页面骨架、操作层级和导航呈现，不改变已确认的
业务模型、数据口径和责任规则。

## 3. 设计目标

### 3.1 用户认知目标

任何业务页面必须让普通用户在五秒内识别：

1. 当前属于哪个业务应用；
2. 当前正在处理什么对象或任务；
3. 当前筛选范围是什么；
4. 下一步可以执行什么操作；
5. 数据处于填报、校验、审核、发布还是归档状态。

### 3.2 企业级视觉目标

- 框架稳定，不随页面内容改变；
- 页面连续，不由多个独立方块拼接；
- 信息密度高，但不拥挤；
- 对齐、边界和状态比装饰更重要；
- 主次操作清楚，颜色克制；
- 同类页面遵循同一骨架；
- 1920px 和 1440px 桌面宽度下都保持专业、完整；
- 1280px 宽度下能够完成核心业务操作。

### 3.3 功能完整目标

去驾驶舱化不授权删除任何已确认业务能力。结构调整必须满足：

- 功能入口可找到；
- 同类功能不重复建设；
- 不同业务不强行组合；
- 同一业务不拆散到多个无关位置；
- 业务字段不因表格列数限制而消失；
- 表格展示摘要，完整内容在同一业务详情或编辑工作区呈现。

## 4. 备选方案与选择

### 4.1 方案 A：继续优化浅色卡片工作台

优点是改动小、摘要醒目。缺点是无法根治驾驶舱感，复杂业务仍会被切成多个
方块，不采用。

### 4.2 方案 B：参考传统企业系统，全部采用深色树形菜单和宽表

优点是信息密度高。缺点是容易产生过深菜单、重复入口和老旧视觉，不原样采用。

### 4.3 方案 C：现代深色 L 形框架加连续表格工作台

采用该方案。它继承参考系统的框架稳定性和表格效率，同时保留现代的可读性、
响应能力、业务状态和可追溯交互。

## 5. 全局企业框架

### 5.1 顶部企业导航

顶部是一条完整的深蓝企业导航栏，高度 44px，不再使用多个大选择框拼接。

从左到右固定为：

1. 平台标识和名称；
2. 当前组织；
3. 六大业务应用；
4. 全局搜索；
5. 我的任务；
6. 通知；
7. 帮助；
8. 当前用户。

六大业务应用固定为：

```text
我的工作｜经营总览｜产情监测｜市场监测｜供需与态势｜报表中心
```

规则：

- 一级应用使用短、稳定的业务文字，不使用只有图标的入口；
- 当前应用使用底部强调线、文字加亮或轻微背景变化；
- 顶部不重复显示“当前业务应用”表单；
- 环境提示只在确有必要时显示为紧凑状态，不形成大标签；
- 组织选择保持紧凑，不写“当前组织”等解释性前缀；
- 全局搜索覆盖区域、监测对象、任务、报告和指标；
- 顶部不展示页面级导入、导出、新建或审核按钮。

### 5.2 左侧业务导航

左侧采用深蓝灰色背景，与顶部连接成连续 L 形框架。

尺寸：

- 展开宽度：152px；
- 折叠宽度：48px；
- 默认展开；
- 用户主动折叠后，在当前会话内保持状态。

职责：

- 只展示当前业务应用内部功能；
- 不重复平台名称、组织、应用说明和业务描述；
- 一级功能采用小图标加文字；
- 只在确有同类子功能时允许展开第二层；
- 不允许出现第三层及更深树形菜单；
- 当前项使用 3px 窄色条、文字加亮和轻背景；
- 菜单顺序按实际工作流程排列，不按技术模块排列。

折叠状态下：

- 显示图标；
- 悬浮显示完整名称；
- 当前项仍必须可识别；
- 不允许依赖用户记忆图标含义完成高风险操作。

### 5.3 内容区

内容区使用浅灰背景和白色工作表面，与深色框架形成稳定边界。

页面从上到下固定为：

```text
面包屑
页面标题＋说明＋页面级操作
业务标签页
筛选区
紧凑状态摘要
主工作表格或主业务单据
分页或保存操作
```

不是每一层都需要外框。标题、标签页、筛选、摘要、工具栏和表格应自然连续，
不分别包装成卡片。

## 6. 去驾驶舱化规则

### 6.1 禁止

- 多列大指标卡片；
- 卡片套卡片；
- 每项风险或待办一个方块；
- 大面积圆角和悬浮阴影；
- 用卡片替代表格、单据或列表；
- 将版本、公式、技术组件或开发状态做成业务模块；
- 在运营页面长期显示“演示版本”“原型组合”“只读预览”等开发过程文案；
- 用空白大面板制造高级感；
- 为了视觉对称重复展示同一数字。

### 6.2 允许

- 经营总览顶部最多四项紧凑数字摘要；
- 数字摘要必须位于一条连续状态带内，不做独立悬浮卡片；
- 严重异常可使用一条警示横幅；
- 单一对象详情可使用分组区块，但不得形成仪表盘网格；
- 供需核心等式可以使用一条连续计算带；
- 地图、趋势图仅在确实用于分析时出现，并与明细表联动。

### 6.3 页面视觉比例

普通业务页面约 80% 空间用于表格、单据和任务处理，约 20% 用于筛选、说明、
摘要和必要分析。经营总览可以提高摘要占比，但仍以任务、异常和正式发布列表
为主体。

## 7. 图标体系

采用“图标加文字分级使用”，不采用全部文字或全部图标。

### 7.1 必须使用文字

- 六大业务应用；
- 左侧业务菜单名称；
- 新建、填报、提交、撤回、审核、驳回、发布；
- 导入、导出、生成报告；
- 表格行中的查看、填报、审核、追溯、催办；
- 任何不可逆或会改变业务状态的操作。

这些操作可以使用“图标＋文字”，但不能只显示图标。

### 7.2 可以只用图标

- 搜索；
- 刷新；
- 列设置；
- 表格密度；
- 展开、折叠；
- 帮助；
- 通知；
- 上一页、下一页。

图标按钮必须具有悬浮说明、键盘焦点和无障碍名称。

### 7.3 视觉约束

- 统一使用线性图标；
- 常规尺寸 14–16px；
- 同一语义只使用一个图标；
- 不混用彩色、填充、立体和卡通图标；
- 图标颜色继承文本，不作为独立装饰；
- 禁止用粮食插画替代业务名称。

## 8. 通用业务页面骨架

### 8.1 清单工作台

适用于样本对象、任务、报告、审核、逾期和历史版本。

结构：

1. 标题与主操作；
2. 业务状态标签；
3. 组合筛选；
4. 应报、已报、待审、阻断、逾期的紧凑摘要；
5. 主表格；
6. 行操作；
7. 分页。

表格首列和关键识别列固定。筛选条件变化后，摘要与表格必须使用同一查询范围。

### 8.2 在线填报工作区

在线填报属于产情或市场的具体业务，不作为第七个应用。

结构：

1. 当前任务、责任区域、责任人、周期和截止时间；
2. 当前监测对象；
3. 品种与商品形态；
4. 价格、质量、数量、库存、加工或物流的连续分组表单；
5. 即时校验信息；
6. 暂存、提交和返回任务清单。

复杂重复数据可使用可编辑表格。字段按业务条件出现，不为不适用角色展示空字段。

### 8.3 Excel 导入工作区

Excel 导入与在线填报写入同一业务单据和同一权威事实，不形成第二套台账。

结构：

1. 下载当前业务模板；
2. 选择地区、周期、对象类型和品种；
3. 上传文件；
4. 预校验结果表；
5. 错误行定位和原因；
6. 确认导入；
7. 导入批次与审计记录。

### 8.4 详情与审核

- 简单查看使用右侧详情抽屉；
- 复杂填报、批量编辑和正式审核使用完整页面；
- 审核页面显示原值、修订值、校验结果和附件；
- 审核中心只组织待办，打开的仍是原业务单据；
- 不复制一份“审核专用业务数据”。

## 9. 六大业务应用页面架构

### 9.1 我的工作

左侧功能：

```text
待我填报｜待我审核｜逾期与催办｜我发起的｜已完成
```

主页面采用任务表格，展示业务、地区、对象、周期、截止时间、状态和下一步操作。
不使用“任务卡片墙”。点击任务进入产情或市场所属业务填报页面。

### 9.2 经营总览

左侧功能：

```text
经营概览｜重点风险｜区域进度｜最近发布
```

经营概览允许一条最多四项的紧凑摘要带，下方依次为：

- 需要立即处理的任务表；
- 区域报送进度表；
- 质量与异常表；
- 最近正式发布列表。

趋势图和地图按分析需要进入对应标签，不与指标卡堆成驾驶舱。

### 9.3 产情监测

左侧功能：

```text
监测总览｜监测对象｜数据采集｜审核与发布｜分析与报告
```

种植生产、农户余粮、农户销售和种植意愿是同一产情业务的内部标签或数据表，
不得继续拆成多个左侧菜单。

产情业务必须保留：

- 玉米、大豆、稻谷；
- 各作物具体品种；
- 面积、单产、产量、生育进度、灾情和长势；
- 农户余粮、销售和种植意愿；
- 与产情相关的质量指标；
- 农户、家庭农场、合作社和农技站等适用对象；
- 在线填报、Excel 导入、审核发布和历史追溯。

监测总览以任务和样本表格为主，不再使用指标卡网格。

### 9.4 市场监测

左侧功能：

```text
监测总览｜监测对象｜数据采集｜审核与发布｜分析与报告
```

价格与质量、库存与加工、物流监测是市场业务的内部标签或专业表格，不得继续
拆成多个左侧菜单。样本对象、在线填报、Excel 导入和系统接入在“数据采集”
工作区内形成一条连续业务链。

市场业务必须保留：

- 三个粮食品类及具体品种；
- 贸易商、深加工企业、压榨企业、蛋白加工企业、食品和调味品企业；
- 饲料企业、养殖企业、储备库、批发市场、米厂和农资经销商；
- 铁路站点和公路物流节点；
- 收购价、销售价、车板价、包粮价、散粮价和适用成交条件；
- 玉米水分、容重、毒素、杂质、不完善粒和霉变；
- 大豆蛋白、水分、杂质和不完善粒；
- 稻谷或大米出米率、出糙率、水分、杂质和不完善粒；
- 数量、库存、每日加工量、开机率、生产线、流入量和流出量；
- 在线填报、Excel 导入、系统接入、审核发布和报告生成。

价格、质量和数量不得拆成互不对应的事实。主表展示摘要，完整事实在同一业务
详情中查看和编辑。

### 9.5 供需与态势

左侧功能：

```text
供需账户｜地区对比｜来源追溯｜平衡校验｜态势分析
```

页面首先显示统一范围：

- 地区；
- 产品；
- 市场年度；
- 统计期；
- 数据版本；
- 发布状态。

供需账户采用：

```text
总供给－总使用＝账面期末库存
```

以一条连续计算带呈现，下方依次为账户明细表、地区贡献表、来源版本表和差异
校验表。不使用一组相互独立的数字卡片。

供需可按授权范围查看区域中心、城市、县区等层级。系统不得让用户误以为只能
查看全部区域，也不得将不同层级数据无说明地混合。

### 9.6 报表中心

左侧功能：

```text
业务报告｜履责报告｜报告复核｜发布与分发｜历史版本
```

业务报告页面提供：

- 业务类型；
- 地区；
- 产品或专题；
- 报告周期；
- 数据版本；
- 日报、周报、月报类型；
- 报告状态。

履责报告页面提供：

- 业务；
- 责任地区；
- 统计期间；
- 履责状态；
- 责任人；
- 周报和月报生成。

两类报告分别服务业务分析和责任监管，但复用同一发布数据与责任事实，不重复
统计或计算。

## 10. 状态、异常和权限

### 10.1 状态表达

状态优先使用文字标签：

```text
未开始｜填报中｜已提交｜待审核｜已驳回｜质量阻断｜已发布｜已逾期
```

颜色只辅助，不作为唯一识别方式。

### 10.2 错误处理

- 筛选失败：保留原条件并显示可重试提示；
- 表格加载失败：在表格位置显示错误，不跳转到空白页；
- 导入失败：精确到工作表、行、字段和原因；
- 保存冲突：提示已有新版本，禁止静默覆盖；
- 权限不足：说明缺少的权限和可联系的责任角色；
- 数据为空：说明当前范围没有记录，并提供调整筛选或创建任务入口；
- 发布阻断：列明未通过的质量、审核或责任条件。

### 10.3 填报责任

- 在同一业务中，每位填报人只承担一个明确责任区域；
- 同一责任区域在同一周期只有一名正式责任人；
- 他人无权代填；
- 每周按规定周期填报；
- 截止时刻形成逾期事实；
- 责任变更只影响未来周期，历史记录不改写；
- 所有填报和履责记录可导出周报、月报。

## 11. 视觉规范

### 11.1 色彩

- 顶部：深蓝；
- 左侧：深蓝灰；
- 内容背景：浅灰；
- 工作表面：白色；
- 主操作：克制的青绿色；
- 警告：琥珀色；
- 阻断和严重错误：红色；
- 成功和正常状态不得大面积铺绿色。

### 11.2 尺寸与密度

- 顶部：44px；
- 左侧：152px，折叠 48px；
- 页面主标题：20–22px；
- 正文与菜单：12–14px；
- 表格正文：12–13px；
- 表格行高：38–42px；
- 常规控件高：30–32px；
- 圆角：2–4px；
- 普通表面不使用大阴影。

### 11.3 对齐与留白

- 页面内容左右边距 16–20px；
- 标题与操作在同一基线；
- 筛选字段按业务顺序排列；
- 数值右对齐，文本左对齐，状态居中或左对齐；
- 单位进入列名或字段标签，不在每个单元格重复；
- 横向滚动只用于确有必要的专业宽表；
- 关键识别列和操作列固定。

## 12. 响应式和可访问性

### 12.1 桌面宽度

- 1920px：完整显示平台名、组织、六大应用、搜索和工具；
- 1440px：缩短搜索宽度，保持六大应用完整；
- 1280px：搜索收为图标入口，左侧可折叠，核心业务不隐藏；
- 小于 1280px：保证查看、填报和审核可用，但不承诺完整桌面宽表体验。

### 12.2 可访问性

- 所有图标按钮具有文字说明；
- 键盘可以访问导航、筛选、表格工具和弹窗；
- 当前焦点清晰；
- 状态不只依赖颜色；
- 表格表头和表单标签语义完整；
- 弹窗和抽屉关闭后焦点回到原操作位置。

## 13. 实施边界

本轮实施优先改造演示系统的统一外壳和六大业务应用页面，不直接修改数据库、
正式后端权限或供需计算服务。

允许：

- 重构统一页面壳、导航、页面骨架和共享组件；
- 调整演示数据的呈现方式；
- 为完整展示已确认业务补充演示记录；
- 合并重复视觉组件；
- 删除仅属于演示或开发过程的界面文案。

不允许：

- 删除已确认业务字段或入口；
- 改写业务口径；
- 用新的统计替代权威发布数据；
- 将填报拆成独立业务应用；
- 将审核复制成第二套业务单据；
- 清除或覆盖用户已有源码改动；
- 直接连接或写入生产数据。

## 14. 验证要求

### 14.1 框架验证

1. 所有页面使用同一顶部、左侧和内容区；
2. 顶部与左侧形成连续 L 形深色框架；
3. 左侧展开宽度不超过 152px；
4. 顶部和左侧没有重复的应用标题或说明；
5. 六大应用均可从顶部进入；
6. 当前应用和当前内部功能都能一眼识别。

### 14.2 去驾驶舱化验证

1. 普通业务页面不存在多列指标卡网格；
2. 风险、待办、样本、报告和责任记录采用列表或表格；
3. 供需只保留一条核心等式，不用独立卡片重复表达；
4. 经营总览摘要不超过四项，并位于连续状态带；
5. 页面不存在卡片套卡片；
6. 版本和开发信息不作为业务模块显示。

### 14.3 业务完整性验证

1. 产情可找到玉米、大豆、稻谷及其具体品种；
2. 市场可找到对应主体、价格、质量、数量、库存、加工和物流数据；
3. 在线填报和 Excel 导入均位于所属业务；
4. 填报任务可追溯到责任人、责任地区、周期和截止时间；
5. 业务日报、周报、月报可以选择业务、地区、产品、期间和版本；
6. 履责周报、月报可以按业务、地区、期间、状态和责任人筛选；
7. 供需可以明确查看当前地区层级和数据版本；
8. 同一业务事实没有第二套统计或重复计算。

### 14.4 视觉和交互验证

1. 主操作使用图标加文字；
2. 通用工具图标具有悬浮说明；
3. 不可逆操作不使用只有图标的按钮；
4. 1440px 宽度无页面级横向溢出，专业宽表除外；
5. 1280px 宽度可完成核心任务；
6. 字体、行高、边框和颜色符合本设计；
7. 加载、空数据、错误、权限不足和保存冲突均有明确反馈。

### 14.5 工程验证

- 现有单元测试继续通过；
- 为统一框架、导航、页面骨架和响应式状态补充测试；
- 六大应用路由可直接访问；
- 构建通过；
- 浏览器逐页视觉核验；
- 不引入无业务价值的重量级依赖；
- 不提交浏览器伴随工具生成的临时对比页面。

## 15. 完成定义

只有同时满足以下条件，才能称为完成：

1. 六大业务应用全部迁移到统一 L 形框架；
2. 所有旧版页面或旧框架均不再从正式演示路由进入；
3. 普通业务页面完成去驾驶舱化；
4. 已确认业务字段、填报方式、责任规则和报告能力无缺漏；
5. 表格、表单、详情、审核、供需和报告使用一致的视觉语言；
6. 自动测试、构建和逐页视觉检查全部通过；
7. 用户能够从新版演示中完成一次完整的查看、填报、审核、发布和报告路径。
