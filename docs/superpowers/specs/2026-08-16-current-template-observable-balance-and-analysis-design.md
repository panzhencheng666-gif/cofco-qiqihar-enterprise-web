# 现有填报模板驱动的可观测供需、产情与市场分析设计

日期：2026-08-16  
状态：待书面审阅  
适用范围：齐齐哈尔粮食商情企业平台本地持续开发分支

## 1. 目标与结论

本设计只改造三个既有菜单：

1. 供需平衡；
2. 产情分析；
3. 市场分析。

三个菜单必须读取同一组“已审核、期间已确认、版本唯一”的业务事实，并随产情、市场、物流记录的审核结果实时刷新。供需平衡是系统自动计算的只读结果，禁止在该菜单录入数值、选择采用来源、填写调整量或人工发布计算值。

责任地区根范围沿用现有主数据中的齐齐哈尔、黑河、呼伦贝尔三地；区县、乡镇和行政村继续由管理员在责任分配中配置，本设计不新建第四套地区数据。

这不是国家级粮食供需平衡表，也不引入当前基层企业调查不到的加工、消费、损耗等新增填报项目。它表达的是“现有业务模板在已调查范围内能够直接观测和推算出的供需关系”，界面名称采用“可观测供需平衡”，并明确覆盖范围，防止把样本调查结果冒充地区全量统计。

## 2. 现状问题

### 2.1 供需平衡

当前实时页面要求业务人员确认来源、填写拟采用数值、填写期末库存调整量并执行试算或发布。该流程把系统分析页面变成了第二个填报入口，形成两份事实，而且“采用值”“批准调整”不能由现有基层调查稳定验证。

### 2.2 产情与市场分析

当前页面的主结构是“从大量指标中任选一个，再看四年对比”。它有以下问题：

- 指标下拉过长，用户必须先懂内部指标体系才知道看什么；
- 一个指标一屏，无法说明面积、单产、产量、长势、灾损、库存之间的关系；
- 市场价格、购销量、库存、运费和质量没有形成业务主题；
- 四年对比被当成主分析，而不是主题中的辅助趋势；
- 缺少数据截止、来源数量、覆盖范围和缺失原因，空白图容易被误解为系统故障。

### 2.3 联动契约

现有供需、年度比较、总览和业务报告存在各自查询及历史计算口径。三个菜单如果继续分别拼装数据，可能出现同一产品、地区、期间显示不同结果。新设计必须建立单一核定事实快照，三个菜单只消费该快照，不在浏览器内重新定义业务公式。

## 3. 范围边界

### 3.1 本阶段包含

- 后端统一核定事实快照与三个只读分析视图；
- 现有产情、市场、物流填报字段到分析事实的受控映射；
- 可观测供需的自动公式、质量状态、覆盖信息和来源追溯；
- 产情分析、市场分析的主题化布局；
- 产品、年份/月、地区的统一可搜索筛选及重置；
- 审核后 SSE 事件驱动的范围级刷新；
- 权限、去重、期间、单位、缺失值和版本一致性门禁；
- 后端、Web、契约和端到端测试。

### 3.2 本阶段不包含

- 云端部署、镜像上传、生产切流或数据库生产迁移；
- 修改已冻结发布候选；
- 域名、证书、EIAM、DNS 或其他云资源变更；
- 新增当前业务模板没有的填报字段；
- 国家级消费、加工、损耗等不可调查项目的伪精确值；
- 改造总览、业务报告、责任地区、账号权限或填报监测页的界面；
- 在普通业务界面显示数据库字段码、技术状态、事件键、治理码或开发说明。

总览和业务报告不是本阶段界面范围，但后续必须复用同一快照契约；本阶段不得为它们建立旁路口径。

## 4. 统一领域语言

- **原始主张**：员工填报或导入的记录，尚未成为正式分析数据。
- **核定事实**：记录处于 `APPROVED`，调查期间处于 `CONFIRMED`，通过字段契约、权限、单位和去重规则后形成的唯一业务事实。
- **核定事实快照**：在产品、地区、调查年/月和数据截止时点内，固定核定事实版本及计算方法的不可变读模型。
- **已调查范围**：实际纳入快照的责任地区、样本点和记录集合，不等同于行政区域全量。
- **可观测供需平衡**：只用现有模板可观测量形成的自动核算结果。
- **推算其他消化量**：区域可观测等式中不能由现有模板分别识别的剩余量；它是系统残差，不是人工填报项，也不得命名为确定的消费或损耗。
- **生产端粮源平衡**：期初库存、预计产量、销售、自用和期末余粮之间的样本级或汇总级勾稽。
- **分析结果版本**：核定事实版本集合、计算方法版本、范围和截止时点共同形成的稳定版本。

禁止继续在新界面使用“手工采用值”“已批准库存调整”“采用后库存”等词。

## 5. 权威数据来源

### 5.1 通用采用条件

事实必须同时满足：

- 记录状态为 `APPROVED`；
- `survey_period_governance_state=CONFIRMED`；
- 产品、地区、年份及可选月份与查询范围一致；
- 使用同一业务键的最新有效记录版本；
- 样本点或业务主体的系统身份可解析，不按名称猜测归并；
- 数值单位能够按批准映射转换；
- 当前登录人员对事实所在地区具有读取权限。

草稿、待审、退回、作废、期间未确认或身份不可解析的记录不进入正式数值。它们只影响“待补数据”提示，不得按零处理。

### 5.2 产情事实

| 业务主题 | 现有字段 | 分析用途 |
| --- | --- | --- |
| 面积 | 播种面积、预计收获面积、灾损面积 | 面积结构、灾损比例、预计产量基数 |
| 产量 | 预计单产、系统预计总产 | 产量、单产和年度趋势 |
| 长势 | 当前长势、生育阶段 | 长势分布和生育进度 |
| 生产端流转 | 期初库存、销售数量、自用数量、期末余粮 | 生产端粮源平衡及勾稽差额 |
| 质量 | 产品适用的水分、容重、毒素、杂质等 | 质量分布，不进入数量等式 |
| 成本 | 地租、种子、农药、化肥、灌溉、人工、机耕、其他成本 | 成本构成，不进入数量等式 |
| 政策 | 补贴、保险 | 生产条件说明，不进入数量等式 |
| 意向 | 下年度意向面积、调整原因 | 意向变化及原因分布 |

预计总产统一按每条核定记录计算：

```text
预计总产（吨） = 播种面积（亩） × 预计单产（公斤/亩） ÷ 1000
```

如果记录已经保存系统计算的预计总产，聚合前必须与该公式在批准精度内一致；不一致则该记录进入阻断清单，不能静默采用任一值。

### 5.3 市场事实

| 业务主题 | 现有字段 | 分析用途 |
| --- | --- | --- |
| 价格 | 采集对象收购价格、采集对象销售价格、车板价 | 均价、区间、地区/主体对比 |
| 交易活动 | 对象类型适用的采购量、销售量 | 市场活跃度与净采购观察 |
| 库存 | 现有库存 | 市场库存水平和期间变化 |
| 流通成本 | 运费、包装形态 | 运费趋势和包装结构 |
| 质量 | 产品适用质量字段 | 市场质量分布 |

市场采购量与销售量是样本主体交易活动，可能与生产端销售、物流流入流出表示同一粮食的不同环节。它们只用于市场分析，禁止直接加进供需总量等式。

### 5.4 物流事实

| 业务主题 | 现有字段 | 分析用途 |
| --- | --- | --- |
| 流向 | 运输方向 | 流入或流出分类 |
| 数量 | 运输数量（吨） | 流入、流出和净流入 |
| 成本 | 物流运价、车板价 | 市场解释指标，不进入数量等式 |
| 结构 | 运输方式 | 运输结构说明 |

在途记录不计入当期流入或流出；方向、地区或期间无法确定的记录进入阻断清单。

## 6. 聚合、去重与覆盖规则

### 6.1 唯一事实键

最低唯一键为：

```text
业务域 + 系统样本点/主体ID + 产品 + 调查年 + 调查月(可空) + 业务字段
```

同一键只采用最高已批准记录版本。记录撤销批准或新版本获批时，旧事实必须退出当前快照，但历史分析版本仍可复现。

### 6.2 年月规则

- 月度查询只采用同月事实；年度记录不能自动填补缺失月份。
- 年度查询对月度事实按字段允许的聚合规则汇总；同一业务键已有年度事实时，不再叠加其月度事实。
- 库存是时点值，年度视图采用范围内最后一个已确认月末值，不求和。
- 价格、单产和质量使用带来源数的平均或加权平均；数量、面积和金额按允许范围求和。
- 缺失值保持 `null` 并附缺失原因；零仅表示业务人员明确填报的零。

数量统一换算为吨，面积为亩，单产为公斤/亩，价格或运费保留其批准的元/吨等单位。正式十进制计算使用服务端任意精度十进制：中间计算不使用二进制浮点，汇总完成后按方法版本统一保留 4 位小数。价格有同口径成交量时使用成交量加权平均，没有可靠权重时使用简单平均并在结果中标明聚合方式。

### 6.3 样本覆盖与防重复

农户、村委会、农技站可能描述重叠范围。每个产品、地区、期间必须有明确的覆盖层级策略：

- 同一统计范围不得混合叠加包含关系的层级；
- 无法判定是否重叠时，数量汇总状态为“覆盖待核对”，不输出伪全量；
- 生产端期末余粮与市场现有库存必须通过系统主体/货权身份进行跨域防重；无法证明互斥时不得相加为期末可观测库存；
- 界面始终显示记录数、唯一样本点数、覆盖行政区数量和阻断记录数；
- 所有总量标签使用“已调查范围”，除非存在经验证的全覆盖配置。

## 7. 自动计算模型

### 7.1 生产端粮源平衡

对每个可勾稽的核定产情事实先逐记录计算，再汇总：

```text
生产可用量 = 期初库存 + 预计总产
已知去向量 = 销售数量 + 自用数量
理论期末余粮 = 生产可用量 - 已知去向量
生产端勾稽差额 = 填报期末余粮 - 理论期末余粮
```

缺少任一必要项时不计算该记录的勾稽差额，缺失项不得当作零。理论期末余粮小于零属于阻断异常。

### 7.2 区域可观测供需平衡

在已调查范围内：

```text
期初可观测库存 + 预计总产 + 物流流入
= 自用数量 + 物流流出 + 推算其他消化量 + 期末可观测库存

推算其他消化量
= 期初可观测库存 + 预计总产 + 物流流入
 - 自用数量 - 物流流出 - 期末可观测库存
```

其中：

- 期初和期末可观测库存使用通过身份归并与防重规则后的库存事实；
- 生产端销售不再单独加入区域等式，避免与市场交易或物流流向重复；
- 推算其他消化量只表达未被当前模板分别观测的剩余量，不拆分为加工、饲料、口粮或损耗；
- 推算其他消化量为负数、库存重复、覆盖阻断或关键输入缺失时，状态为“暂不可形成可靠结果”；
- 页面不得提供人工修正入口。

### 7.3 市场观察公式

```text
样本净采购量 = 采购量 - 销售量
库存期间变化 = 当前期现有库存 - 上一可比期现有库存
收购销售价差 = 平均销售价 - 平均收购价
```

这些是市场观察指标，不写入供需数量等式。

## 8. 统一读契约

三个菜单共同调用一个只读快照接口：

```http
GET /api/v1/observable-analysis/snapshots
    ?productCode=
    &regionCode=
    &surveyYear=
    &surveyMonth=
    &cultivarCode=
    &subjectTypeCode=
```

响应的业务结构如下，字段名是接口契约，不直接展示给普通用户：

```text
scope
  product, region, surveyYear, surveyMonth,
  cultivar(optional), subjectType(optional)
version
  analysisVersion, methodologyVersion, dataCutoffAt, generatedAt
quality
  state, blockingReasons, warnings, recordCount,
  uniqueSubjectCount, coveredRegionCount, excludedRecordCount
production
  area, yield, output, growth, damage, stage,
  openingInventory, sales, selfUse, endingInventory,
  productionReconciliation, quality, cost, intention
market
  purchasePrice, salePrice, boardPrice,
  purchaseVolume, saleVolume, netPurchase,
  currentInventory, inventoryChange, freight, quality
logistics
  inflow, outflow, netInflow, freight, transportModes
supply
  openingObservableInventory, expectedOutput, inflow,
  selfUse, outflow, endingObservableInventory,
  inferredOtherAbsorption, state
lineage[]
  domain, recordId, recordVersion, factCodes,
  subjectLabel, regionLabel, periodLabel, approvedAt
```

约束：

- 后端返回已经完成单位换算和业务计算的字符串十进制数；Web 不使用二进制浮点重新计算正式结果；
- 每个数值携带单位、来源数、聚合方式和缺失原因；
- `analysisVersion` 对同一事实集合与方法版本必须稳定；事实或方法改变后必须改变；
- 不返回内部主体键、稳定身份键、事件键、治理字段码或私有附件键；
- 历史现有接口保留兼容读取，三个新菜单切换完成后不得继续旁路读取旧供需人工决策接口。

## 9. 三个菜单的信息架构

### 9.1 共同筛选区

第一行只保留高频条件：产品/作物、数据年份、数据月份、责任地区。地区使用可输入搜索的地级市—区县—乡镇—行政村级联，展示名称，不展示一串地区代码。

提供：

- “重置”按钮，恢复当前授权范围及最近存在核定数据的期间；
- “更多条件”折叠区，仅放样本点类型或具体品种等非必要条件；
- 当前范围摘要；
- 数据截止、更新时间、来源数、覆盖状态和实时连接状态。

切换父级地区必须清空不再属于该父级的子级选择。没有数据时保持所选范围，不借用其他地区或日期的数据。

### 9.2 可观测供需平衡

页面顺序：

1. 结果状态卡：可形成结果、待补数据、覆盖待核对或异常；
2. 关键指标卡：预计总产、净流入、期末可观测库存、推算其他消化量；
3. 供需桥图：期初库存 → 预计产量 → 流入 → 自用/流出 → 推算其他消化 → 期末库存；
4. 生产端勾稽：理论期末余粮、填报期末余粮、差额和异常记录数；
5. 覆盖与质量：记录数、样本点数、覆盖地区、阻断原因；
6. 来源明细折叠表：业务名称、地区名称、期间、版本、采用字段和审核时间。

页面只有筛选、刷新、查看来源和导出当前结果等只读动作。禁止出现填数、确认来源、调整、试算和发布按钮。

### 9.3 产情分析

主结构按业务问题分区，不显示全量“分析指标”下拉：

1. **生产概况**：播种面积、预计收获面积、加权预计单产、预计总产；面积/产量组合图；
2. **长势与灾损**：长势分布、生育阶段分布、灾损面积与灾损比例；堆叠条形图；
3. **余粮与去向**：期初库存、销售、自用、期末余粮和生产端勾稽差额；流向图或分组柱图；
4. **质量与成本**：产品适用质量指标、亩均成本构成、补贴和保险；箱线/区间与成本堆叠图；
5. **下年种植意向**：意向面积与当前面积对比、调整原因分布；对比柱图与原因排名。

每区最多保留 2–4 个与问题匹配的图表，并附确定性文字摘要。四年对比放在每区的“年度趋势”子页，不再作为全页唯一主体。

### 9.4 市场分析

页面分区：

1. **价格运行**：平均收购价、平均销售价、价差、车板价；趋势线和地区区间图；
2. **购销活动**：适用主体的采购量、销售量和样本净采购量；分组柱图；
3. **库存监测**：现有库存、上一可比期库存和变化；趋势与地区对比；
4. **流通成本**：运费趋势和包装形态分布；
5. **市场质量**：产品适用质量指标分布；
6. **地区与主体对比**：按授权地区及样本点类型查看，但不把不同适用字段强行比较。

每区明确来源数与适用对象。缺少采购量或销售量的对象类型不按零参与净采购计算。

## 10. 图表与文字的分工

- 指标卡回答“现在是多少”；
- 图表回答“构成、变化和差异是什么”；
- 规则化文字回答“哪些变化值得注意，以及数据是否完整”；
- 来源表回答“结论来自哪些核定记录”。

文字摘要只能由确定性规则生成，例如同比方向、最大地区、覆盖不足和勾稽异常。不得生成无法从快照复核的推测性结论，也不在界面展示“AI分析”“算法调试”“开发中”等开发痕迹。

## 11. 实时联动

### 11.1 触发条件

以下状态变化必须产生可持久追踪的业务事件：

- 产情、市场、物流记录获批；
- 已批准记录被作废或批准被撤销；
- 同一业务键的新版本获批；
- 调查期间确认状态改变；
- 计算方法版本正式切换。

事件必须包含可授权过滤的业务域、产品、地区、调查年/月、记录版本和单调递增序号，但 Web 普通内容区不展示这些技术字段。

### 11.2 Web 行为

- SSE 只通知“哪个范围失效”，正式数值仍通过只读快照接口重新获取；
- 按事件序号去重，同一序号只处理一次；
- 只刷新与当前筛选相交的范围；
- 事件游标出现缺口时执行当前范围的完整重新读取；
- 断线时明确显示“实时连接已断开，当前显示截至某时的数据”，并提供重连；
- 重连采用有上限的退避并带最后游标，不用静默旧数据冒充实时；
- 多标签页收到同一事件后应得到相同 `analysisVersion`。

## 12. 权限与审计

- 普通员工只能读取其责任地区内的快照与来源摘要；
- 审批管理员可查看授权范围的来源明细和阻断记录；
- 任何分析接口都必须执行服务端地区隔离，不能依赖前端隐藏；
- 来源明细只显示业务名称、地区、期间、版本和审核时间，不泄漏内部身份键；
- 快照保留方法版本、事实版本摘要、生成时间和计算校验摘要，支持历史复现；
- 本阶段没有供需写接口，也不授予普通用户供需修改权限。

## 13. 状态与失败语义

统一质量状态：

- `AVAILABLE`：关键输入完整、没有阻断异常，可显示正式结果；
- `PARTIAL`：可显示部分分析，但必须列出缺失项，供需结果不能标为完整；
- `COVERAGE_REVIEW_REQUIRED`：来源层级重叠或覆盖无法判定；
- `BLOCKED`：负残差、单位冲突、重复库存、身份不可解析、期间冲突或公式不一致；
- `NO_APPROVED_DATA`：当前范围没有核定事实。

网络失败、权限不足、契约不匹配和无业务数据必须有不同提示。任何失败都不得自动借用别的地区、产品、年份或旧版本结果。

## 14. 数据库与迁移

- 只能新增前向迁移 `V121__...` 及以后版本；禁止修改 `V1`–`V120`；
- 新投影或方法表不能覆盖原始记录；
- 旧供需人工决策表可保留历史只读兼容，但新菜单不得写入；
- 新快照必须能够从现有核定记录重建；
- 迁移测试覆盖 fresh `V1→latest` 和 `V120→latest`；
- 本地迁移通过不构成云端迁移授权。

## 15. 验收矩阵

### 15.1 后端单元与契约测试

- 面积×单产的公斤到吨换算与精度；
- 生产端粮源平衡、可观测供需等式及负残差阻断；
- 市场交易不进入供需总量；
- 库存时点值不求和，年度/月度不重复；
- 缺失值不按零、层级重叠阻断、最高批准版本唯一采用；
- 不同菜单查询同一范围返回相同 `analysisVersion`；
- 私有治理字段不进入响应；
- 地区权限越权返回拒绝而非空白伪成功。

### 15.2 Web 组件测试

- 三页统一筛选、搜索地区、父子级联和重置；
- 供需页不存在数值输入、来源确认、调整、试算和发布控件；
- 产情/市场按主题呈现，没有巨大扁平指标下拉；
- `AVAILABLE/PARTIAL/BLOCKED/NO_APPROVED_DATA` 分别展示正确；
- 图表、文字摘要、来源数和来源表使用同一响应；
- 业务界面不出现内部字段码、地区代码墙或开发术语；
- SSE 断线、重连、重复事件、游标缺口和范围外事件行为正确。

### 15.3 端到端验证

至少用两个账号完成：普通员工和审批管理员。

1. 员工提交产情、市场或物流记录；三个菜单保持旧正式版本；
2. 管理员审核通过；对应范围收到事件并刷新；
3. 三个菜单显示同一数据截止和分析版本；
4. 修改并审核新版本；旧版本退出当前快照，历史版本可复现；
5. 撤销或作废后结果相应回退；
6. 未授权地区不可读取；
7. 两个浏览器标签页最终结果一致；
8. 导出当前分析范围与页面数值一致。

### 15.4 回归门禁

- Web 全量测试与现有阶段门禁继续通过；
- Backend JDK 21 全量测试继续通过；
- 产情、市场、物流填报/审核/导入既有契约不回归；
- frozen release candidate 不发生任何修改；
- 不执行云端变更。

## 16. 实施顺序

1. 先用失败测试固定快照契约、单位与公式；
2. 新增后端核定事实查询和只读快照，不改 Web；
3. 用契约测试验证三域来源、权限、版本与缺失语义；
4. Web 接入统一类型和仓储接口；
5. 先替换供需页为只读自动结果；
6. 再重构产情与市场主题布局；
7. 接入 SSE 范围失效刷新；
8. 运行全量回归和端到端联动；
9. 形成仅本地版本检查点，等待独立发布授权。

## 17. 完成条件

本设计只有在以下条件同时满足时才算实现完成：

- 三个菜单使用同一核定事实快照；
- 供需结果完全自动、只读、可追溯；
- 产情与市场能用图表、确定性文字和来源表解释现有填报数据；
- 审核后当前范围实时刷新，断线状态不伪装正常；
- 结果的覆盖、缺失、异常、版本和截止时点可见；
- 普通界面没有业务范围外字段、内部码、开发痕迹或第二套人工事实；
- 契约、权限、实时、端到端和全量回归全部通过；
- 变更只存在于隔离本地分支，没有进入云端。
