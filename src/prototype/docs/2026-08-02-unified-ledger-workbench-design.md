# 粮食商情统一列表工作台设计

## 目标

把产情、市场、物流、供需和报表中心统一为成熟企业系统的列表工作台。用户进入页面后应依次完成“选择条件、查看台账、处理记录或展开分析”，不再阅读重复说明、状态摘要或开发过程信息。

## 统一页面结构

1. 页面标题与主要业务动作。
2. 一条紧凑查询栏，只展示当前页面完成查询所需的核心条件。
3. 台账标题，显示当前业务对象、地区、期间和记录数量。
4. 数据表格或唯一的空状态。
5. 行内查看、编辑、复核或展开分析，不增设与表格重复的卡片。

## 查询栏规范

- 查询字段使用统一的控件高度、字体、间距和两档宽度：常规字段统一宽度，地区级联使用适中加宽。
- 标签与控件作为不可拆分的字段单元；标签不得挤入相邻控件。
- 查询、重置、保存常用条件作为一个完整操作组，始终位于查询容器内。
- 宽屏优先单行；空间不足时按字段单元整组换行，操作组单独换行并右对齐；禁止控件或按钮溢出页面。
- 产情、市场、物流、供需和报告使用同一响应式规则，不允许页面自行定义互相冲突的列宽。

## 产情与市场分析

两个分析页面采用同一条业务路径：

1. 核心筛选：业务分类、业务地区、产品或作物、分析期间。
2. 已核定数据默认由系统按所选范围匹配；需要追溯时放入“更多条件”，不占据首屏主路径。
3. 查询后直接显示“四年同比指标台账”。
4. 台账包含当前值、前三年值、相邻同比、当前较前三年、三年复合增长率、数据依据和操作。
5. 点击指标行展开同比趋势图和口径说明；图表不独立堆放在首屏。

删除重复的数据状态说明、当前条件复述、零项统计条和多份空结果提示。未完成必要选择时，只在台账区域显示一条可执行的空状态提示。

## 业务报告

业务报告采用“选择范围后生成”的列表工作台：

- 核心条件：业务、地区、产品或专题、报告类型、报告期间、采用的已核定数据。
- 业务分类、具体品种、报告模板和报告章节作为依赖条件；仅在业务需要时通过“更多条件”展示。
- 数据截止时间随采用数据自动显示，不单独形成大块容器。
- 生成报告作为查询栏主要动作。
- 日报、周报、月报以及填报记录周报、月报统一收纳到“生成与导出”菜单。
- 下方只保留待编辑报告与历史报告台账，不再增加重复的选择摘要区。

## 数据与权限

- 保留现有全部有效业务字段、授权地区、产品、具体品种、业务对象、期间、已核定数据、报告模板和章节。
- 内部编码、技术版本号、开发状态和不可解释的数据标识不得暴露给业务用户。
- 超出授权范围、缺少已核定数据或无操作权限时，在动作附近给出一条明确原因，不复制多处提示。

## 验收标准

- 常用桌面窗口下查询条件和操作按钮全部位于容器内，标签、控件互不重叠。
- 同类筛选框尺寸一致，地区控件不过度拉长。
- 产情分析、市场分析和业务报告首屏没有重复说明、重复状态层或驾驶舱卡片。
- 三个页面均可沿“筛选—台账—操作”一眼识别业务流程。
- 原有查询、重置、保存常用条件、生成报告、导出和指标展开能力可用。
- 关键组件测试、类型检查、构建和浏览器交互检查通过。
