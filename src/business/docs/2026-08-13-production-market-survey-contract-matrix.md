# 产情、市场与物流调查四端业务契约矩阵

基线：当前 Web 固定业务表结构、`businessApplicability.ts` 的对象类型适用性，以及 Backend 各业务域的显式公共字段白名单。本文只规定普通业务界面和 XLSX 的受审核白名单；数据库字段、产品路由维度、稳定主体键、权属、货权、政策、审计和事件字段继续保留，但不得据 `displayed/group/order` 自动进入普通列表、表单或工作簿。

### DEF-160 产情契约候选原子门禁

现场 RED 的真实 payload 为 `production-survey-fields-v1`、CORN/FARMER、41 个公共字段。Backend 已正确过滤 `PROD_SAMPLE_SUBJECT_CODE` 等私有字段，旧 Web 解析器却要求该私有字段必须存在，因而把合法响应误判为 `INVALID_PRODUCTION_FIELD_BOUNDARY`，页面继续渲染照片区并形成“只剩照片”。同时，运行中的 Maven 子 JVM曾混用新 Controller 与旧 Domain class，旧记录详情触发 `NoSuchMethodError: ProductionRecord.surveyYear()`；两者都属于非原子候选，不是照片组件故障。

修复后的门禁如下：

- 解析器要求所有批准的公共核心字段、属性和顺序完整，拒绝重复、乱序、组内悬空、非公开字段及稳定主体/余粮治理/附件/兼容日期键；Backend 增加元数据不会自动进入 UI。
- 契约请求切换时先清空旧 definition 并进入 `loading`；只有同一请求成功解析后的 definition 才能原子进入 `loaded`。`failed` 时业务字段和照片区都不渲染，保存禁用并显示明确错误。
- 真实 63182 合法 DOM 显示数据时间、基础信息、填报与定位、面积与长势、测产与产量、品种质量、余粮销售使用、种植意向、成本、补贴保险及现场照片；必填值与 1 张照片就绪后原生表单有效，预计总产即时同值。
- 真实响应删去 `PROD_REPORTER_PHONE` 的浏览器反例得到字段组 0、照片输入 0、保存禁用；合法响应不再被误判。
- 旧记录真实详情返回年/月、系统填报日期和受权照片，DOM/API 均不含稳定主体码、`sample_point_id`、`EXT/DEF/RS`、英文治理枚举或内部账号/节点键。

## 市场字段及对象类型适用性

基础固定为：序号、数据时间、填报日期、样本点名称、样本点类型、地区；市场业务界面不展示或要求“具体品种”，质量字段使用记录所在产品路由；末尾固定为填报状态、操作。中间业务字段只取下列适用矩阵。

| 对象类型           | 适用业务字段                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------- |
| 贸易商             | 采集对象收购价格、采集对象销售价格、采购量、销售量、车板价、运费、包装形态；对应品种质量；现有库存 |
| 深加工/米厂/饲料厂 | 采集对象收购价格、采集对象销售价格、采购量、车板价、运费、包装形态；对应品种质量；现有库存         |
| 养殖场             | 采集对象收购价格、采集对象销售价格、采购量、车板价、运费、包装形态；对应品种质量；现有库存         |
| 批发市场           | 销售量、采集对象收购价格、采集对象销售价格、车板价、运费、包装形态；对应品种质量；现有库存         |
| 储备企业           | 采集对象收购价格、采集对象销售价格、车板价、运费、包装形态；对应品种质量；现有库存                 |

市场价格语义固定为样本点的“采集对象收购价格”和“采集对象销售价格”。总揽聚合分别使用样本点平均收购价与样本点平均销售价；兼容用无方向中间价不得作为正式业务卡片。

普通市场采集明确排除 `MKT_CULTIVAR_NAME`、`PROCESSING_INPUT`、`MAIN_OUTPUT`、`BYPRODUCT_OUTPUT`、`PROCESSING_LOSS`、`OPERATING_RATE`、`DIRECT_USE_VOLUME`、`STOCK_OUTFLOW`。这些历史字段不做破坏性数据库删除，但不得进入在线表单、列表和 XLSX 普通业务内容区。`ENDING_INVENTORY` 在业务界面唯一显示为“现有库存”，含义为“截至所选数据时间的现有库存”，不得另设“库存量”或“期末库存”。`MKT_STORAGE_REGION_CODE`、权属、货主、截止日期和政策字段继续保留为内部治理契约；新记录有现有库存时从业务地区自动填入存放地区，旧记录保留原值，普通业务界面不得显示这些字段。

## 物流字段

物流公共契约的 16 个业务字段及固定顺序为：数据年份（必填）、数据月份（可空）、填报日期（系统生成）、物流样本点名称、地区、填报人（系统绑定）、填报人联系方式、物流样本点联系方式、纬度、经度、运输方式、运输方向、运输数量（吨）、物流运价（不含车板价，元/吨）、车板价（元/吨）、填报状态（系统生成）。退回原因只在退回详情中按既有工作流展示，不是填报或导入字段。纬度范围为 -90—90，经度范围为 -180—180。

`LOG_FREIGHT_RATE`只表示不含车板价的物流运价，`LOG_BOARD_PRICE`只表示独立车板价；两者分别持久化、导入、返回与聚合，不相加、不推导、不复用编码。`LOG_PERIOD`、`LOG_COLLECTION_DATE`、`LOG_ORIGIN`、`LOG_DESTINATION`、`LOG_TRANSIT_TIME`仅保留为历史版本兼容字段，不进入在线填报、列表、详情/审核或普通 XLSX。产品码只作为服务端锁定的内部路由、隔离及聚合维度保留；普通用户不得填写或看到“产品品种”。填报人由登录员工默认且服务端绑定，账号ID、节点ID和内部位置键不得返回到业务内容区。

物流 XLSX 模板固定使用上述 16 个同名、同序中文列。数据年份及 12 个业务输入列可填写，数据月份可空；填报日期、填报人、填报状态明确标为系统生成/只读，导入若试图覆盖即拒绝。服务端仅按审核后的固定列位置映射内部字段，不把英文技术字段码写入可见或隐藏工作表。三类工作簿的业务域、产品、对象类型和契约版本上下文也只写中文业务值，服务端通过受审核双向映射还原内部值并继续执行防串用校验，未知映射拒绝生成或导入。物流只保留“下载 XLSX 模板”和“导入 XLSX”；本轮误加的物流业务导出按钮、Web API、Backend `/api/v1/logistics-records/export`、服务及测试已完整删除。该删除不影响产情、市场既有导出。

## DEF-158 四类可追踪门禁

### 1. 同类型模块

产情、市场、物流必须分别使用上表的独立表面矩阵验收；任一类的页面或测试不得替代另一类证据。物流当前公共契约已接入正式 runtime；产情库存与数据时间本轮已形成 V118 本地链路证据，但三类仍有正式页面、既有导出及端到端消费者证据缺口，因此 DEF-153/155/156/157 均保持 `OPEN_LOCAL`。

### 2. 全部业务表面

每类逐项追踪监测表/筛选/分页/照片、在线新建编辑、详情审核退回状态、XLSX 模板导入导出错误回显、用户可见校验及地区权限。`不适用` 必须明确：物流业务导出按用户指示删除；物流照片入口沿当前产品无该业务能力，不新增旁路；系统生成字段不允许导入或编辑。
